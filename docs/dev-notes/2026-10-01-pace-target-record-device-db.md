**날짜**: 2026-10-01
**범위**: 기능 개발이 아니다. 사용자가 오늘 뛴 기록을 확인해 달라 했고, 이어서
"1분 30초 당기면 몇 분이냐" → "그 목표치로 기록을 하나 더 만들어 달라" 로 갔다.
**앱 코드는 한 줄도 안 고쳤다. 커밋 없음.** 바뀐 것은 기기의 로컬 DB 한 행과
이 노트뿐이다.

## 2. 페이스 계산 — 1'30" 당기면 20:24

- 목표 페이스 = 9'28" − 1'30" = **7'58" /km**
- 2.56 km × 478초 = 1,223.7초 = **20:24** (현재보다 3분 48초 단축)
- 구간 기준: 1km 7:58 · 2km 15:56 · 완주 20:24

> 표시된 `2.56 km / 24:12` 를 직접 나누면 **9'27"** 이 나온다(앱 표시는 9'28").
> 소수점 반올림 차이다. 9'27" 기준이면 목표가 7'57" / 20:21 이라 **3초 차**뿐이라
> 실주행 목표는 "20분 20초대 초반" 으로 잡으면 된다.

## 3. 🟢 기기 DB 에 쓰는 길을 찾았다 — 릴리스가 디버그 키로 서명돼 있다

막힌 길부터 전부 확인했다. **추측으로 건너뛴 게 없다.**

| 길 | 결과 |
|---|---|
| `run-as` 로 직접 | ❌ `package not debuggable` — 설치된 건 릴리스 |
| 루팅 | ❌ `su` 없음 (`/system/xbin/su`·`/system/bin/su` 둘 다 없음) |
| Supabase 에 넣고 내려받기 | ❌ **동기화가 업로드 단방향**. `run_sync_service.dart` 에 `upsert` 만 있고 `select` 가 없다 |
| 앱의 수동 기록 추가 | ❌ `records.md` 에 그런 기능이 없다 |
| 디버그 APK 로 교체 | ✅ **데이터 보존된다** |

돌파구는 `android/app/build.gradle.kts:44` 였다.

```kotlin
release {
    // TODO: Add your own signing config for the release build.
    // Signing with the debug keys for now, so `flutter run --release` works.
    signingConfig = signingConfigs.getByName("debug")
}
```

**릴리스가 별도 keystore 없이 디버그 키로 서명된다.** 서명이 같으니 디버그 APK 를
`adb install -r` 로 덮어써도 서명 불일치가 안 나고, 따라서 **uninstall 이 필요
없다** — 러닝 기록도 로그인도 그대로 남는다. 그 상태에서는 `run-as` 가 열린다.

`firstInstallTime=2026-08-30 22:22:46` 이 디버그 설치 → 릴리스 복귀 **전 구간에서
불변**이었다. CLAUDE.md 가 경고한 "uninstall 하면 기록 날아감" 을 건드리지 않았다.

> 이 서명 사실을 모르면 "데이터를 날리지 않고는 DB 를 못 본다" 고 잘못 결론내고
> `adb backup` 같은 불안정한 길로 샌다. **앞으로 기기 DB 를 봐야 할 때의 정석이다.**

## 4. 🔴 디버그 APK 의 env 검증에 `grep -a` 를 쓰면 **거짓 음성이 난다**

CLAUDE.md 는 설치 전 `grep -a "<SUPABASE_URL 호스트>" <apk>` 로 env 주입을 확인하라고
한다(9/27 §14 의 사고 때문에 박아둔 규칙이다). 그대로 했더니 **0 건**이 나왔다.

```
$ grep -ac "djrklqjdwsfyszuxgltf.supabase.co" app-debug.apk
0
```

**그런데 env 는 제대로 박혀 있었다.** APK 는 ZIP 이고, 디버그 빌드는 Dart 코드가
`assets/flutter_assets/kernel_blob.bin` 안에 **deflate 압축되어** 들어간다. 원시
바이트를 훑는 `grep` 에 잡힐 리가 없다.

zip 엔트리를 풀어서 확인하니 바로 나왔다.

```
찾음: 'djrklqjdwsfyszuxgltf.supabase.co'
  assets/flutter_assets/kernel_blob.bin  (1회, compress_type=8)
```

`compress_type=8` 이 deflate 다. 582개 엔트리 중 이 하나에만 들어 있다.

**릴리스에서 `grep -a` 가 통했던 이유**는 릴리스는 Dart 코드가 `libapp.so` 로
가고 `.so` 는 APK 에 **무압축 저장**되기 때문이다. 즉 CLAUDE.md 의 그 방법은
**릴리스 전용**이고, 디버그에 쓰면 멀쩡한 빌드를 "env 빠졌다" 고 오판하게 된다.

> **9/27 과 정반대 방향의 함정이다.** 그때는 env 가 **없는데** 앱이 멀쩡해 보였고,
> 오늘은 env 가 **있는데** 검증이 없다고 말했다. 둘 다 "앱을 켜서는 알 수 없다" 는
> 점이 같다 — **파일을 직접, 압축을 풀어서 본다.**

## 4-1. Git Bash 가 `/data/...` 를 Windows 경로로 바꿔버린다

첫 DB 추출이 405,504 바이트가 아니라 **115 바이트** 로 나왔다. 열어보니 내용이
`cat: C:/Program Files/...` 였다. MSYS 가 `/data/data/...` 를 Windows 경로로
변환해 기기가 아니라 PC 경로를 `cat` 한 것이다.

**`MSYS_NO_PATHCONV=1`** 를 붙이면 해결된다. 조용히 깨지는 종류라 —
`adb` 는 성공으로 끝난다 — **파일 크기와 헤더를 매번 확인**해야 한다.

```
$ head -c 16 run_earth.sqlite | od -c
0000000   S   Q   L   i   t   e       f   o   r   m   a   t       3  \0
```

### 5-1. 서버로 안 올라가게 한 방법

사용자가 "로컬에만 둔다" 를 골랐다. 대기 목록은 별도 큐 테이블이 아니라
**`runs.synced_at IS NULL`** 로 표현된다(`run_sync_service.dart:16`,
`app_database.dart:166` 의 `syncedAt.isNull()`). 그래서 **`synced_at` 에 값을 채워
넣으면 업로드 대상이 아예 안 된다.** 원본의 값을 그대로 복사했다.

화면에서 '동기화 대기' 뱃지가 안 뜨는 것으로 확인했다.

### 5-2. 사진은 파일을 복사했다 — 공유하면 안 된다

사진 파일명이 **`photo_{runId}.jpg` 로 id 에 묶여 있다**(`cover_storage.dart:24`).
한 파일을 두 행이 가리키게 두면 **한쪽 기록을 지울 때 다른 쪽 사진이 깨진다.**
그래서 새 id 이름으로 파일을 복사했다.

## 6. 확인된 것 — 0km 정책이 화면에서 실제로 돌고 있다

`durSeconds < 60` 이면 '미완료' 로 보고 목록 기본 숨김 + 통계·스트릭에서 제외한다.

빠진 4건은 전부 `0.0km / 00:05·00:07` 류였다. **버그가 아니라 설계대로다.**
9/20 에 정하고 구현한 정책이 2주 뒤 실기기 데이터에서 그대로 작동하는 걸 확인한 셈.

## 8. 결정해둔 것 (다시 올리지 말 것)
