## 1. 알림 권한 — 서비스는 뜨는데 알림만 막혀 있었다

매니페스트에 `POST_NOTIFICATIONS` 를 추가하고, START 직전에 런타임 요청을
붙였다. 시스템 팝업 **전에** 왜 필요한지 먼저 설명하는 다이얼로그를 둔다 —
안드로이드는 두 번 거부당하면 영구 거부라, 맥락 없는 팝업은 비용이 크다.

**거부해도 러닝은 막지 않는다.** 알림 없이도 추적 자체는 되므로 차단은 과하다.
대신 "화면을 끈 사이 기록이 끊길 수 있어요" 경고를 띄운다. (위치 권한은 거부 시
시작을 **막는다** — 이쪽과 정책이 다르다는 걸 `run-flow.md` 6장에 명시했다.)

| 지표 | 9/18 | 지금 |
|---|---|---|
| `numPostedByApp` | 0 | **1** |
| `numBlocked` | 1 | **0** |

### ⚠️ `permission_handler` 는 12.0.3 에 묶여 있다

최신(13.0.2)을 넣었더니 빌드가 깨졌다:

```
Dependency ':permission_handler_android' requires ... version 37 or later
:app is currently compiled against android-36.
maximum recommended compile SDK version for AGP 9.0.1 is 36
```

`permission_handler_android` 14 부터 compileSdk 37 을 요구하는데 AGP 9.0.1 의
권장 최대가 36 이다. 툴체인을 건드리는 대신 **12.0.3 으로 내렸다**(android 구현
13.0.1). 이유는 `pubspec.yaml` 주석에 남겼다. 올리려면 **AGP → compileSdk 순서로
함께** 올려야 한다.

## 3. ✅ 스플래시 타임아웃 — 실측으로 유실을 재현하고 막았다

기다리는 **장소**를 옮겼다. 홈으로 먼저 보내고 복원은 뒤따르게 한다. 홈은 탭바가
있어 갇히지 않으므로 시간 제한 없이 끝까지 기다려도 안전하다.

타임아웃 값을 늘리는 건 답이 아니었다 — 느린 기기에서 또 터지고 스플래시만
길어진다. 3초 타임아웃 자체가 9/14 에 **위젯 테스트의 무한 대기를 막으려고** 넣은
것인데, 테스트를 살리려던 장치가 실기 동작을 깎아먹은 셈이었다.

### 재현 방법과 증거

러닝 중 강제 종료 → **에뮬레이터 콜드 부팅**(`-no-snapshot-load`) → 앱 실행.

```
13:57:03  FlutterJNI: Beginning load of flutter...
13:57:26  FlutterGeolocator: Creating service.    ← 복원이 여기서 일어났다
```

**복원이 엔진 시작 23초 뒤**다. 옛 코드였다면 3초에서 포기하고 이 러닝을 통째로
잃었다. 가정이 아니라 실측이다.

## 4. ✅ 복원은 항상 일시정지 상태로 (§5 [미확정] 해소)

사용자가 "복원됐다가 홈에서 그냥 앱을 강제 종료하면 기록이 어떻게 되냐"고 물어서
코드를 따라가다 드러난 문제다. **기록 자체는 안 사라진다**(스냅샷을 지우는 곳은
정식 저장 성공 후와 6시간 만료 확정 후 딱 두 군데뿐). 그런데 복원되면 경과
타이머가 다시 돌아 **안 뛴 시간이 계속 쌓인다.**

이제 스냅샷이 running 이었어도 **항상 paused 로 되살린다.** 복원 시점의 사용자는
이미 뛰기를 멈춘 쪽이 보통이다 — 폰이 꺼져 충전하고 돌아온 경우가 대표적이다.

화면에 일시정지 배지와 RESUME 버튼이 이미 있어, "묻지 않고 조용히 복원"이라는
7장 원칙과 충돌하지 않는다.

> 3장(홈 먼저 보내기)의 대가인 "홈이 잠깐 보였다 전환되는 구간"도 이걸로
> 무해해진다. **두 변경은 묶어서 해야 한다** — 3장만 적용하면 오히려 더 나쁘다.

### 검증

| 확인 | 결과 |
|---|---|
| 거리 보존 | 0.21km (스냅샷 0.20851) ✅ |
| 경로 폴리라인 | 지도에 복원 ✅ |
| 복원 상태 | 일시정지됨 배지 + RESUME ✅ |
| 18초 방치 후 | 시간 **00:59 그대로** ✅ |
| RESUME 후 | 01:06 으로 진행, 거리 0.21km 유지 ✅ |
| STOP 후 | `active_runs` 0행, 기록 저장 + 동기화 대기 ✅ |
| `flutter test` | TimeoutException 로그 소멸 ✅ |

## 5. 🟡 새로 찾은 것 — 콜드 스타트에 흰 화면이 번쩍인다

복원 검증 중 스크린샷에 잡혔다. 다크 앱인데 OS 런치 화면이 흰색이다.

- `drawable-v21/launch_background.xml` = `?android:colorBackground` (테마 추종)
- `values/styles.xml` LaunchTheme parent = **`Theme.Light.NoTitleBar`** → 흰색
- `values-night/styles.xml` 만 `Theme.Black.NoTitleBar`

앱 UI 는 시스템 테마와 무관하게 **항상 다크**(`AppColors.background #070911`)인데,
런치 화면만 시스템 설정을 따른다. **폰이 라이트 모드면 흰 화면이 번쩍인 뒤 다크
앱이 뜬다.** 전부 `flutter create` 기본값 그대로다.

→ 고치려면 LaunchTheme 을 양쪽 다 다크로 두거나 `#070911` 색을 직접 지정하면
된다. 이번 범위 밖이라 손대지 않았다.

## 6. 출발 전 화면 — 날씨 값이 전부 가짜였다

사용자가 "온도 글자가 좀 올라가 있는 것 같다"고 해서 열어보다 두 가지가 나왔다.

### ① 🔴 날씨·미세먼지가 하드코딩이다

`'24°'` `'체감 26°'` `'보통'` 전부 문자열 리터럴이다. `lib/` 어디에도 **날씨 API
연동이 없다** — 서비스도 패키지도 provider 도 없다. Figma 프로토타입의 목업 값이
그대로 넘어왔다. 한겨울에 켜도 24° 가 뜬다.

문서상으로는 실제 기능이 맞다. `기능정의서` 4-2 섹션 B 에 **미세먼지 4단계 상태
바 + 배경색**(`나쁨` 주황 / `매우나쁨` 빨강)까지 정의돼 있고, `offline-handling.md`
18 줄에도 "네트워크가 필요한 부가 정보"로 잡혀 있다. **미구현 상태다.**

→ 붙이려면 **어떤 API 를 쓸지** 정해야 한다. 문서에 없다. 기상청 단기예보 /
OpenWeatherMap / 에어코리아 등 + API 키 발급.

### ② 카드 세로 정렬 버그 (`9cd383b`)

`Column` 의 `mainAxisSize` 기본값이 **`MainAxisSize.max`** 다. `_MiniCard` 가
높이 64 로 고정돼 있어 Column 이 세로를 꽉 채우고, 기본 정렬(`start`)이 글자를
위로 밀었다. 반면 `Row` 는 아이콘을 중앙에 놓으니 해와 온도가 어긋나 보였다
(텍스트 중심이 카드 중심보다 **약 14dp 위**).

미세먼지 카드도 같은 원인으로 위에 붙어 있었다. 두 Column 에
`MainAxisSize.min` 을 줘 해결.

> Flutter 기본값이라 눈에 안 띈다. **고정 높이 컨테이너 안의 Column 은
> `mainAxisSize` 를 의심할 것.**

## 7. GPS 를 바로 잡게 고쳤다 (`f1c6743`)

"달리기할 때 위치를 10초 뒤에 갖고 오지 말고 바로 갖고 오자"는 요청에서 출발했다.

**먼저 사실관계**: 코드에 위치 관련 10초는 없다. 10초는 스냅샷 저장 주기이고,
위치는 3초 간격이었다. 늦게 느껴진 진짜 원인은 셋이었다.

| # | 원인 | 조치 |
|---|---|---|
| ① | `distanceFilter: 5` 가 **위치 수신 자체**를 막음 | 스트림은 0, 5m 검사는 누적할 때만 |
| ② | 배지 조건이 `route.length < 2` | `current == null` 로 변경 |
| ③ | GPS 를 카운트다운 **끝난 뒤**에 켬 | 카운트다운 시작과 함께 켬 |

### ①이 핵심이다 — 필터 위치를 옮겼다

5m 를 **스트림 입구**에 걸면 그만큼 움직이기 전까지 위치가 아예 안 들어온다.
지도도 배지도 같이 멈춘다. 출발선에 서 있으면 신호가 멀쩡한데 "GPS 신호를
기다리는 중"이 계속 떴다.

```
[전]  GPS ──[5m]──→ 지도 + 거리      ← 하나가 둘 다 막음
[후]  GPS ─────────→ 지도            ← 3초마다 무조건
           └─[5m]──→ 거리·경로       ← 여기서만 검사
```

**값은 그대로다. 거르는 위치만 옮겼다.** 정지 중 노이즈 방어는 유지된다.

### 캐시 위치는 지도 전용이다

`getLastKnownPosition()` 으로 지도를 즉시 채운다. **거리·경로에는 절대 넣지
않는다** — 몇 시간 전 수 km 떨어진 값일 수 있어, 경로에 넣으면 첫 실제 fix 까지의
직선거리가 통째로 잡힌다.

### 덤: 복원 시 지도가 엉뚱한 곳을 비췄다

복원 후 `current` 가 비어 있어 지도가 폴백(서울시청)을 봤다. 9/18·9/19 검증에서
모의 좌표가 하필 서울시청이라 **눈치채지 못했다.** 마지막 경로 좌표를 기준점으로
주도록 고쳤다.

### 검증

| 확인 | 결과 |
|---|---|
| 움직이지 않고 START | 배지 7초 내 사라짐 ✅ |
| ±2m 지터 8회(정지 중 노이즈) | 거리 **0.00km 유지** ✅ |
| 30m × 6회 이동 | **0.18km** — 180m 정확히 일치 ✅ |

> ⚠️ **캐시 위치 효과는 증명 못 했다.** 에뮬레이터는 모의 GPS 라 첫 fix 가 즉시
> 오고, 모의 좌표가 폴백과 같아 구분이 안 된다. 이 개선은 첫 fix 가 수 초~수십 초
> 걸리는 **실기기 야외에서만** 확인된다.

## 8. 기록 상세 화면 (`4adde59`)

기록 카드를 눌러도 **아무 일도 일어나지 않았다.** 그 탓에 "RunDetailView 가
아직 없어…" 로 시작하는 임시 조치가 문서 두 곳에 쌓여 있었고, 대표 이미지
교체 기능은 진입로가 없어 통째로 막혀 있었다.

### ⭐ 새로 만들 게 아니었다

기능정의서 5 가 이 화면을 달리기 종료 화면과 **같은 공유 컴포넌트**로 정의하고
있었고, `run_screen` 의 `_Result` 가 이미 그 절반이었다. 꺼내서 `RunDetailView`
로 만들고 양쪽이 쓴다.

| | 달리기 종료 | 기록 상세 |
|---|---|---|
| 닫기 | ✕ → prerun 초기화 | ← → 목록 복귀 |
| 아래 | 안내 문구 + 완료 버튼 | 없음 |

> 계획 전에 문서를 안 읽었으면 화면을 통째로 새로 짰을 것이다. 일이 절반으로
> 줄어든 게 아니라, **두 화면이 갈라져 따로 놀 뻔한 걸 막았다.**

### 경로 PNG 가 여태 사장돼 있었다

러닝마다 1080px 경로 PNG 를 만들어 저장하는데 **그걸 표시하는 화면이 없었다.**
기록 카드는 텍스트만 보여준다. 상세 화면이 생기며 비로소 쓰인다 — 다만 저장된
PNG 를 읽지 않고 `route` 좌표로 **매번 다시 그린다**(2026-09-11 결정). 렌더가
실패했거나 파일이 사라진 기록도 정상 표시된다.

### 대표 이미지 변경 버튼은 뺐다

`run-flow.md` 5 의 바텀시트는 "사진으로 변경 / 경로 이미지로 변경" 두 갈래인데,
사진 기능이 없어 **모든 기록이 이미 경로 이미지다.** 전환할 대상이 없어 눌러도
아무 일도 하지 않는 버튼이 된다. 사진 기능을 붙일 때 바텀시트와 함께 만든다.

## 9. 환경에서 걸린 것들 (다음에 또 겪지 않게)

### ① Git Bash 가 adb 기기 경로를 윈도우 경로로 바꾼다

```
$ adb exec-out run-as com.runearth.run_earth cat /data/data/.../run_earth.sqlite
cat: C:/Program Files/Git/data/data/...: No such file or directory
```

pull 한 파일이 115바이트짜리 에러 메시지였고 `file is not a database` 로 터졌다.
**`MSYS_NO_PATHCONV=1` 을 붙여야 한다.** (9/18 노트의 같은 명령이 안 통하는 이유.)

```bash
MSYS_NO_PATHCONV=1 adb exec-out run-as com.runearth.run_earth \
  cat /data/data/com.runearth.run_earth/app_flutter/run_earth.sqlite > snap.sqlite
```

기기에는 `sqlite3` 바이너리가 **없다.** pull 해서 호스트에서 파이썬으로 연다.

### ② XML 주석은 태그 **안**에 못 넣는다

`<application` 과 `android:label` 사이에 주석을 넣었다가 빌드가 깨졌다
(`Error parsing LocalFile: AndroidManifest.xml`). 주석은 태그 위로. 커밋 전
`python -c "import xml.dom.minidom as m; m.parse('...')"` 로 확인하면 싸게 잡힌다.

### ③ UI 자동화 탭은 스플래시를 기다려야 한다

8초 대기 후 탭했는데 아직 스플래시라 빗나갔다. **16~18초로 늘려도 또 빗나갔다** —
세션 중 세 번 반복됐다. 콜드 부팅 후에는 30초 넘게 걸리기도 한다.
고정 대기는 답이 아니다. **탭 전에 스크린샷으로 화면을 확인**할 것.

### ⑤ 이 저장소는 `dart format` 을 쓰지 않는다

카드를 `GestureDetector` 로 감싸며 들여쓰기가 틀어져 `dart format` 을 돌렸더니
무관한 변경이 **200줄 넘게** 섞였다. 확인해보니 `lib/` 59개 파일 중 **23개가
포맷터 출력과 다르다** — 애초에 포맷터를 쓰는 저장소가 아니다.

```bash
dart format --output=none --set-exit-if-changed lib/   # 23 changed
```

→ 되돌리고 바뀐 블록만 손으로 들여썼다. **앞으로도 돌리지 말 것.** 도입하려면
전체를 한 번에 정리하는 별도 커밋이어야 한다.

### ④ System UI ANR 이 또 났다 — 이번엔 메모리가 원인이 아니다

9/18 에 RAM 을 4096 으로 올렸고 `MemAvailable` 이 2.29GB 였는데도 떴다. 빌드 직후
호스트 부하가 겹친 시점이었고, `Wait` 로 넘기니 재발하지 않았다. 9/18 의 처방은
유효하되 **ANR 이 곧 메모리 문제는 아니다.**

저 배너는 사실이 아닌 안내가 된다.

2026-08-15 작성본이 local-first 확정 **전**의 가정을 담고 있었던 것이고, 같은
문서 §4 의 "로컬이 1차 진실 소스"와도 모순이었다. §6 완료 조건에도 틀린
체크박스가 남아 있어 그대로 구현했으면 없어도 될 배너를 만들 뻔했다.

콘텐츠 탭은 원래 정책을 유지했다 — 지금은 내장 샘플이라 오프라인에서도 뜨지만
(이미지만 원격이라 실패), 서버 데이터로 바뀌면 케이스 C 가 그대로 맞다.
