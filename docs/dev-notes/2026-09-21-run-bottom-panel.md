## 2. Figma 를 그대로 따르지 않은 2건 (사용자 결정)

### ① 시간의 `.43` — 넣지 않는다

Figma 는 `00:18` 뒤에 1/100초를 작게 붙인다. 그런데 트래커는 **1초 단위로
틱한다**(`run_tracker.dart` `_startElapsedTimer`). 1/100초를 그리려면 화면용
고속 타이머(50ms 이하)를 따로 돌려야 하는데, 이 화면은 포그라운드 서비스로
**몇십 분씩 켜져 있는** 화면이다. 배터리 값이 얻는 것보다 크다.

> 레이아웃은 Figma 그대로 두고 소수 span 만 뺐다. 나중에 넣고 싶으면
> `_LiveStats._item` 에 span 하나만 붙이면 된다.

### ② 일시정지 중 '종료' — 남긴다

Figma 는 일시정지하면 버튼 그리드가 **전체폭 '달리기 재개' 하나로** 바뀐다.
즉 **일시정지 상태에서는 종료를 못 한다.** `run-flow.md` 에는 규정이 없다.

멈춰서 숨 고르다 그대로 끝내는 흐름이 흔한데, 재개를 거쳐야만 끝낼 수 있으면
막다른 길이 된다. **재개(전체폭) + 그 아래 종료** 로 했다 — Figma 의 재개
버튼은 그대로 살리면서 종료 경로를 잃지 않는다.

### 넣지 않은 것: 카운트다운 0 의 `GO!`

Figma 는 0 에서 `GO!` 를 700ms 보여준다. 트래커는 **1 다음 바로 running** 으로
넘어가므로, 넣으려면 상태 머신에 단계를 더하고 시작을 0.7초 늦춰야 한다.
화면이 아니라 **로직 변경**이라 따로 판단이 필요하다. 체크리스트에 남겨뒀다.

## 6. 홈 디테일 (체크리스트 4번, `0a882f8`)

### `maxConsec` 은 새 필드가 아니었다

체크리스트에 "`StreakInfo.maxConsec` **필드 추가 필요**"로 적어뒀는데 **잘못

> 앞 세션이 "필드가 필요하다"고 적어둔 항목은 **그대로 믿지 말고 모델을 한 번
> 열어볼 것.** 이 한 줄 때문에 "데이터 모델 변경이라 물어봐야 한다"고 판단해
> 작업 시작을 한 번 미뤘었다.

### 진행바는 직접 그려야 했다

`LinearProgressIndicator` 로는 **마커를 바 밖으로 못 내보낸다.** Figma 의 흰 점
마커(12)가 바(6)보다 커서 위아래로 삐져나오는 구조라, `LayoutBuilder` +
`Stack` 으로 직접 그렸다. 채움도 단색에서 `#00A854 → #00E87A` 그라데이션으로.

### 스트릭 카드는 '최고 연속 색'이 기준이다

이번 주 최고 연속 일수의 색 하나가 카드 전체를 지배한다 — 🔥 크기와 glow,
카드 배경 radial glow, 오늘 점, 오늘 날짜 글자색이 전부 이 색을 따른다.
연속이 쌓일수록 카드가 초록 → 주황 → 핫핑크로 달아오른다.

**Figma 대로 못 한 것**: 원 안쪽 `inset` 그림자. Flutter `BoxShadow` 에는
inset 이 없어 바깥 glow 만 넣었다.

**불꽃 크기 기준값을 바꿨다**: Figma `11 + maxConsec×1.4` → `15 + maxConsec×1.4`.
구현이 이미 15 였고, Figma 값을 그대로 쓰면 **연속 0일일 때 지금보다 작아진다.**
앱 전체 글자가 Figma보다 한 단계 큰 것과 같은 맥락이다.

## 9. 구간별 페이스 (KM splits, `9e58109` + `0f129bc`)

체크리스트 6번 중 splits. **적재(1단계)와 화면(2단계)을 나눠서** 했다.

### 왜 이것부터 했나

6번의 세 항목(사진·splits·심박수) 중 **splits 만 미루면 되돌릴 수 없다.**
구간 페이스는 좌표마다 시각이 있어야 나오는데, 그 시각은 **달리는 그 순간에
적어두지 않으면 나중에 복원할 방법이 없다.** 미루는 동안 쌓이는 기록은 영영
splits 를 못 본다. 사진은 반 년 뒤에 붙여도 과거 기록에 넣을 수 있고,
심박수는 애초에 워치가 있어야 한다.

### 좌표 타입을 나누지 않고 선택 필드로

`LatLngPoint` 를 러닝 경로(`Run.route`)와 테마 코스(`ThemeRun.courseRoute`)가
함께 쓴다. 코스 좌표는 미리 그어둔 선이라 시각이 성립하지 않는다.

러닝 전용 타입을 새로 파는 대신 **선택 필드**로 갔다 — 경로를 그리는 코드가
여러 화면에 흩어져 있어(`route_painter`·`run_detail_view`·`records_screen`·
`run_screen`) 타입을 나누면 그걸 전부 두 타입 받게 고쳐야 한다.
사용자 결정(2026-09-21).

### 🟢 스키마 변경이 필요 없었다 — 내가 잘못 알렸던 것

작업 전에 "저장 구조가 바뀌니 **기존 기록을 옮기는 작업**이 필요하다"고
말씀드렸는데 **틀렸다.** 경로는 칼럼 하나에 **JSON 문자열로 통째** 들어간다
(`app_database.dart` `_encodeRoute`). 칸이 느는 게 아니라 그 문자열 안에 키가
하나 붙을 뿐이라 마이그레이션이 없고, `t` 없는 예전 기록도 그대로 읽힌다.
동기화도 좌표를 `toJson` 으로 통째 올려 자동으로 따라간다.

> **저장 방식을 먼저 열어보고 말할 것.** 코드를 안 보고 "스키마 변경"이라고
> 단정해 작업을 실제보다 크게 보이게 만들었다.

### 🔴 `t`(벽시계)만으로는 안 됐다 — 일시정지

1단계를 끝내고 화면을 만들려다 드러났다. `t` 는 벽시계라 **쉰 시간이 그대로
들어 있다.** 2km 에서 5분 쉬면 그 구간만 페이스가 `11'20"`(실제 `6'20"`)로
튀고, 화면에 뜨는 총 시간(일시정지 제외)과도 어긋난다.

거리 쪽은 이미 `_skipNextSegment` 로 일시정지 구간을 빼고 있어 **시간만 맞추면
됐다.** 좌표에 `e`(달린 시간 = 시작부터 누적, 일시정지 제외)를 하나 더 넣었다.
`t` 는 남겼다 — 서버 GPS 재검증·웨어러블 병합에는 벽시계가 필요하다.

| 필드 | 뜻 | 쓰임 |
|---|---|---|
| `t` | 벽시계(UTC epoch ms) | 서버 재검증·웨어러블 |
| `e` | 달린 시간(일시정지 제외) | **구간 페이스** |

> 1단계를 "끝냈다"고 하고 넘어갔는데 2단계에서 구멍이 나왔다. **화면까지
> 그려보기 전에는 적재가 충분한지 알 수 없다.**

### 1km 경계는 보간해야 한다

1km 지점은 좌표와 좌표 **사이**에 걸린다. 경계를 넘은 좌표의 시간을 그대로
쓰면 그 구간이 실제보다 길어지고, **그 오차가 뒤 구간으로 계속 밀린다.**
좌표 구간 안에서 경계가 걸리는 비율로 선형 보간했다.
한 번에 여러 경계를 넘는 경우(신호가 끊겼다 돌아옴)도 처리한다.

### 🔴 막대가 전부 비어 나왔다 — 9/20 §12 와 같은 함정

`구간별 페이스` 첫 판에서 막대 채움이 **하나도 안 그려졌다.** 원인은
**자식 없는 `DecoratedBox` 가 느슨한 제약에서 0×0 으로 접힌 것** —
`Stack` 자식으로 위치 지정 없이 넣어 높이를 못 받았다.

**어제 내가 쓴 노트(9/20 §12)에 똑같은 함정이 적혀 있었다.**
`Positioned.fill` + `heightFactor: 1` 로 꽉 찬 제약을 주어 해결.
