## 1. 오늘 완성한 것

### 1-A. users 테이블 연동 — 커밋 `892247f`

서버 `public.users` 생성(`auth.users.id` 를 PK 로 참조, RLS `auth.uid() = id`).

**신규** `lib/features/auth/data/user_repository.dart`
- `ensureUserRow()` — 행이 **없을 때만** insert. upsert 가 아닌 이유: 프로필에서
  닉네임을 바꿔도 다음 로그인 때 소셜 이름으로 덮어써지는 사고를 막기 위함.
- `loadCurrentUser()` — 서버 조회 실패(오프라인 등) 시 **세션 메타데이터로 폴백**.
  이름이 아예 안 뜨는 상황을 만들지 않는다.
- `currentAppUserProvider` — 로그인/로그아웃 이벤트마다 자동 재조회.

**호출 지점 2곳**: 신규 로그인(`AuthService.signInWithGoogle`) + 기존 세션(스플래시).
스플래시는 최소 노출 시간과 병렬 + 5초 타임아웃이라 오프라인에서도 진입을 막지 않는다.

**수정**: 홈 인사말 하드코딩 제거, 프로필 `_UserCard` 이름·아바타 실데이터.

**검증(에뮬 Pixel 9 API35)**: 홈 `RUNEARTH님`, 프로필에 구글 아바타 렌더,
Supabase `users` 행 1건 생성 확인.

### 1-B. 러닝 기록 서버 동기화 — 커밋 `7fb48a6`

서버 `public.runs` 생성 + 로컬 DB v2 → v3(`synced_at` 컬럼).

**신규** `lib/services/sync/run_sync_service.dart`
- 대기 목록 = `runs.synced_at IS NULL`
- 트리거 2곳: 앱 시작(스플래시), 러닝 저장 직후. 둘 다 결과를 기다리지 않는다.
- 커버 이미지는 **올리지 않는다** — 현재 값이 이 기기의 로컬 파일 경로라 다른
  기기에서 무의미하고, `route` 좌표만 있으면 `route_image_renderer` 로 다시
  그릴 수 있어 Storage 자체가 불필요.

**개발용 샘플 제거**: `_seedRunsProvider`·`records_sample_data.dart` 삭제 +
마이그레이션에서 기존 `seed-%` 행 삭제. 동기화를 켜면서 가짜 기록이 서버로
올라가면 안 되기 때문. 실제 러닝(`run_*`)은 보존.

**검증**: 마이그레이션 후 홈 총 횟수 **10회 → 3회**(샘플 7건만 삭제, 실제 3건 보존),
Supabase `runs` 에 3건 업로드 확인(`user_id`·타입·거리·페이스 정상), 동기화 에러 로그 없음.

### 1-C. 서버 스키마 SQL 기록 — 커밋 `cf6176c`

`supabase/migrations/` 에 오늘 실행한 SQL 2개 + README. 지금까지 대시보드에서
손으로 만들어 저장소에 적용 내역이 없던 문제를 해소.

> ⚠️ CLI 미도입 상태라 **자동 적용이 아니라 기록**이다. 스키마 변경 시
> "대시보드 실행 + 파일 추가"를 둘 다 해야 저장소와 서버가 어긋나지 않는다.

## 2. 오늘 내린 결정 (승인받음)

| 항목 | 결정 | 이유 |
|---|---|---|
| `User.streak` 서버 컬럼 | **두지 않음** | 로컬 기록에서 계산되는 파생값. 서버에 복제하면 로컬 계산값과 어긋난다. 코드에서 `AppUser.streak` 는 실제로 아무 데서도 안 쓰이고 있었음. 푸시/랭킹이 필요해지면 그때 서버에서 `runs` 로 재계산 |
| `avatar` | 구글 프로필 **URL 그대로 저장**(Storage 복사 X) | 만료돼도 이모지 폴백으로 충분. 프로필 사진 직접 업로드를 넣을 때 어차피 Storage 를 붙이게 됨 |
| `apple_watch`/`galaxy_watch` | 컬럼 유지 | streak 과 달리 **계산 불가한 저장 상태**. 사용은 MVP 이후 |
| 동기화 재시도 | 횟수 제한 없음, 간격 30초→1분→5분(앱 실행 중) | 장시간 오프라인에서 횟수로 포기하면 그 기록은 영영 못 올라간다 |
| 동기화 후 로컬 정리 | **정리 안 함(영구 보관)** | 로컬이 1차 진실 소스. 기록 탭이 오프라인에서도 보여야 함. 1건 수 KB 라 용량 무의미 |
| 큐에서 1건 실패 시 | **건너뛰고 다음 진행** | 깨진 한 건이 뒤의 모든 기록을 인질로 잡는 상황이 더 나쁨 |
| 대기 목록 구현 | `SyncQueueItem` 별도 테이블 대신 **`synced_at` 플래그** | 올릴 대상이 `run_upload` 하나뿐. 큐 테이블은 같은 데이터를 두 곳에 두는 비용만 생김. 필요해지면 플래그와 **공존하게 추가** |
| 로컬 샘플 기록 | `seed-%` **7건만 삭제**, 실제 3건 보존 | 처음엔 10건 전부 샘플인 줄 알았으나 7건만 시드였음. 남은 3건은 오히려 업로드 큐 검증용 실데이터가 됨 |

> `offline-handling.md` §4·§5 의 `[미확정]` 3건은 이 결정으로 확정해 **문서에 반영 완료**.
> 그 문서들은 2026-08-15 에 코드 없이 일괄 작성된 기획 초안이고, `SyncQueueItem`
> 은 "개발자 확인 필요 영역"으로 열어둔 항목이었다.

## 3. ⚠️ 진행 중 / 향후 염두

### 3-1. 검증 안 된 가장 큰 미지수 — 야외 GPS
실기기 야외 러닝 검증을 **아직 못 했다**(08-30 시도했으나 실내라 신호 미확보).
거리·페이스 계산이 실제로 맞는지 아무도 모르는 상태. 만약 여기에 버그가 있으면
**이제는 그 틀린 데이터가 서버에까지 올라간다** → 우선순위 최상.

### 3-2. 프로필 탭 통계가 아직 샘플값
홈은 실데이터인데 프로필의 `247.3km / 98h / 38회` 는 여전히 `profile_sample_data.dart`.
홈과 숫자가 다르다. 배지도 샘플.

### 3-3. 이전 노트에서 이어지는 미해결
백그라운드 추적, 칼로리(몸무게 필요), 일시정지 세그먼트 미분리, 날씨/미세먼지
하드코딩, RunType 고정, `gpsVerified=false`, iOS 지도·로그인 키(Mac 필요),
홈 CTA `onTap` 비어있음, 여정 히어로에 탭 라벨 비침(원인 미확정),
이미지 Unsplash 임시(journey.md §4 `[미확정]` 확정 후 교체).

### 3-4. 아직 안 만든 오프라인 UX
`synced_at` 으로 "동기화 대기 중" 상태를 표현할 수 있게 됐지만, 전역 오프라인
배너와 대기 배지(offline-handling.md §2 케이스 B·C, §3)는 미구현.
`connectivity_plus` 등 새 패키지가 필요하다.
