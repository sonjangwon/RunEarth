## 1. 요청 3건

### ① 테마 카드 사진을 마라톤 히어로와 같은 96 으로 (`799bc86`)

두 탭을 오가면 사진 덩어리 높이가 80 과 96 으로 어긋나 보였다.
**Figma 정본이 서로 다른 값**인데 사용자 결정으로 테마 쪽을 올렸다(결정 ⑥).

덤으로 마라톤 카드 라운드 `16` → `12`(결정 ⑦). 9/20 에 기록 카드를 12 로

### ② 홈 하단 여백 (`8bdffc6`)

**패딩 문제가 아니었다.** CTA 아래가 화면의 1/4 쯤 비는데, 원인은 고정 높이
스택이 요즘 기기의 세로를 못 채우는 것이었다.

> **Figma 로는 풀 수 없는 문제다.** Make 의 폰 프레임은 **320×640**
> (`App.tsx` `PhoneShell`)이라 히어로 104 로도 홈이 거의 꽉 찬다. Pixel 9 는
> 411×923dp 라 같은 스택이 뜬다. 화면 크기 차이에서 오는 문제라 Figma 에
> 답이 없어 따로 정했다(결정 ⑧).

남는 세로를 **여정 히어로가 먹는다**(104 → 최대 220). 여정이 이 앱의
주인공이고 104 에서는 도시 사진도 너무 낮게 잘렸다.

- 에뮬레이터 실측: 빈 공간 **224dp → 약 110dp**
- 노트8(1080×2220)에서는 화면이 더 짧아 **여백이 거의 없다** — 같은 상수로
  두 기기가 다 맞았다

기준값 `_contentHeightAtHeroMin`(545)은 **Pixel 9·기본 글자 크기 실측**이다.
글자 크기 설정이 다르면 어긋나지만 `clamp` 로 104~220 에 가둬 밖으로는 안 나간다.

### ③ 0km 기록 정책 개정 (`f9db704`)

9/20 결정을 뒤집는 요청이라 먼저 근거를 말씀드렸고, 그래도 진행하라 하셔서
했다. 판정에서 **시간 조건(`durSeconds < 60`)을 빼고 거리만** 본다.

| 유형 | 예시 | 2026-09-20 | 2026-09-23 |
|---|---|---|---|
| 잘못 눌렀다 만 것 | 22초 · 0.00km | 접는다 | 접는다 |
| 뛰었는데 GPS 를 못 잡은 것 | 1분 37초 · 0.00km | **남긴다** | **접는다** |

**맞바꾼 것이 분명하다.** 잃는 것은 GPS 를 못 잡은 날의 스트릭이고, 얻는 것은
보이는 것과 세는 것의 기준이 하나라는 점이다. 기준이 둘이면 목록에 카드가
7 개인데 '총 횟수 8회' 같은 어긋남이 생긴다.

판정 하나가 목록·요약·홈 통계·스트릭에 모두 쓰이므로 **스트릭에서도 빠진다**
— 이것도 같이 확정했다(사용자 결정).

에뮬레이터 실측: 미완료 5 → **7건**, 총 횟수 8 → **6회**, 총 시간
0h24m → **0h14m**. 펼쳐도 요약 통계는 6회 유지(문서 요구사항대로).

되돌리려면 `isIncomplete` 에 `&& durSeconds < 60` 을 다시 넣으면 된다.
`durSeconds` 는 총 시간 합산에도 쓰여 그대로 남아 있다.

세로로 쌓이고(DISTANCE/PACE/TIME), 경로는 우하단 작은 글리프로 물러난다.

- 히어로 우상단 카메라 버튼 → 바텀시트(촬영/갤러리)
- picker 파일은 **캐시 폴더**라 OS 가 지울 수 있다. 문서 폴더로 복사해 둔다
- iOS `Info.plist` 에 카메라·사진 보관함 설명 추가 — 없으면 고르는 순간 앱이
  죽는다. **Mac 이 없어 빌드 검증은 못 했다**

**화면을 열어보고 2건 고쳤다**(정적 분석은 둘 다 통과했었다):

- 상단 어둠 Figma `0.5` → **`0.65`**(결정 ⑨). 흰 하늘 사진에서 '일반'
  뱃지(외곽선만 있는 칩)가 묻혔다. Figma 목업 사진이 어두워서 안 드러나던 문제다
- 바텀시트를 **루트 Navigator** 로. 탭 셸 Navigator 에 띄우니 시트 아래쪽이
  탭 바에 가렸다

### 🟢 Android 는 카메라 권한 다이얼로그가 없다

`camera-permission.md` 는 "권한 다이얼로그 → 허용/거부"를 전제로 쓰였는데
**실제로는 그 단계가 없다.** `image_picker` 가 카메라 앱을 **인텐트로** 띄워서

- 오히려 `CAMERA` 권한을 선언하면 **없던 다이얼로그가 생긴다** → 매니페스트에

- 갤러리도 시스템 사진 선택기라 권한이 필요 없다
  ("This app can only access the photos you select" 안내가 뜬다)
- **iOS 는 다르다** — plist 키가 없으면 죽는다

실측을 `camera-permission.md` 8-1 에 남겼다.

### 2단계 — 양방향 전환 + 결과 화면 (`aeb76c1`)

정본 둘을 **한 시트에 합쳤다** — `camera-permission.md` 3 의 등록 시트
(촬영/갤러리)와 `run-flow.md` 47-48 의 변경 시트(사진/경로). camera 문서가
"기존 '사진으로 변경' 자리에 촬영 옵션을 더한다"는 취지라 충돌이 아니다.

**경로로 되돌려도 `coverImageUrl` 을 지우지 않는다.** 경로 이미지는 좌표로
그리므로(2026-09-11 결정) 그 칸이 비어도 되고, 사진 경로를 남겨두면
"등록한 사진으로 되돌리기"로 다시 고르지 않고 돌아올 수 있다 —
`run-flow.md` 27-28 의 "자유 전환"이 이 뜻이다. 사진인지 경로 PNG 인지는
파일 이름(`photo_` / `route_`)으로 가린다.

결과 화면은 DB 를 구독하지 않아 저장된 `Run` 을 직접 들고 있는다. 저장은 경로
PNG 렌더 뒤 **비동기**라, 저장이 끝나기 전에는 카메라 버튼을 아예 안 그린다.

**검증**: 기록 상세에서 등록 → 경로로 변경 → 사진으로 되돌리기까지 전부
화면으로 확인. 결과 화면 배선은 그날 못 봤지만(§4 의 에뮬레이터 ANR 탓)
🟢 **야외 검증에서 실제 야간 사진으로 확인됐다**(§8).

### 🔴 테마런 상세가 회색 판으로만 보였다 (`8f07232`)

테마 카드를 눌러도 화면이 통째로 에러 위젯이 됐다. 릴리즈라 회색으로 보였고,
디버그였으면 빨간 에러 화면이었을 것이다.

`_ThemeRunDetail` 이 `Positioned.fill` 을 **직접 돌려줬는데**, 그 사이에
`AnimatedSwitcher` 와 `SlideTransition` 이 끼어 있어 **Stack 의 직계 자식이
아니게 된다.** 노트8 logcat 에서 `Positioned.applyParentData` 예외 확인.

화면을 덮는 책임을 부모로 옮겼다 — `Positioned.fill` 이 Stack 바로 아래에서
`AnimatedSwitcher` 를 감싸고, 상세 위젯은 평범한 위젯을 돌려준다.

> 상세 안의 "경로 미리보기 (코스 좌표 필요)" 빈 칸은 **의도된 것**이다.
> 백로그의 "코스 실측 GPS 좌표는 콘텐츠팀 작업" 항목.

### 🔴 출발 전에 지도가 통째로 없었다 (`b1b258f`)

Figma 는 지도를 **항상** 띄워두고 아래 패널만 출발 전 ↔ 달리는 중으로 바꾼다
(`App.tsx` 853줄 MAP · 869줄 BOTTOM PANEL). 우리는 달리는 중에만 지도가 있어서,
**어디서 달릴지 보지도 못한 채 START 를 눌러야 했다.**

- 지도+패널을 `_MapWithPanel` 공용 레이아웃으로 묶고 출발 전도 태운다
- GPS 뱃지를 출발 전에도. `GPS 연결됨`, 아직 못 잡았으면 `GPS 연결 중…`
  — Figma 는 늘 '연결됨'이지만 못 잡았는데 그렇게 말할 수는 없다
- 버튼 `START` → **`달리기 시작`**(Figma 940줄)

출발 전 지도는 **캐시 위치로만** 채운다. 권한을 새로 묻지 않는다 — 묻는 시점은
START 이고(`run-flow.md` 6), 탭을 구경만 해도 팝업이 뜨면 정책과 어긋난다.

화면 확인 중 하나 더 고쳤다. `🛰 GPS 신호를 기다리는 중…` 이 출발 전에
**영원히** 떠 있었다. 출발 전에는 위치 스트림을 돌리지 않아 기다려도 채워지지
않는다. 달리는 중에만 띄운다.

> 9/20 "전수 조사"도 9/21 3번 작업도 **달리는 중 패널만 보고** 출발 전은
> 비교한 적이 없었다. `figma-alignment.md` 에 3-1 항목을 새로 팠다.

## 4. 에뮬레이터에서 달리기 종료 시 ANR — 🟢 §8 에서 해소

사진 모드 2단계의 **결과 화면 배선을 화면으로 확인하지 못했다.** 결과 화면에
가려면 달리기를 끝내야 하는데, 에뮬레이터에서 **종료할 때마다 ANR** 이 났다.

```
Subject: Input dispatching timed out ... Waited 5006ms for MotionEvent
main 스레드: LocationManager.removeNmeaListener → binder transact 에서 블록
```

**geolocator 가 추적을 중단하는 경로**이고 스택에 우리 사진 코드나 Flutter
프레임은 없다. 9/21 §5 의 geolocator FGS ANR 과 같은 계열인데 **그때는 시작
쪽이었고 이번은 종료 쪽**이다.

이후 에뮬레이터의 `system_server` 가 재시작됐고, 콜드 재부팅 뒤에도
**System UI isn't responding** 이 반복돼 더는 신뢰할 수 있는 검증이 안 됐다.
앱 자체는 재실행 시 스냅샷 복원(일시정지됨)까지 정상이었다.

- 에뮬레이터 부하 탓일 가능성이 높지만 **단정하지 않는다**
- 야외 검증 항목에 **"종료할 때 ANR"** 을 더한다

> 🟢 **실기기에서 한 번도 안 났다**(§8). 시작·달리는 중·종료 전부 깨끗했고
> dropbox 에 앱 ANR 기록이 0건이다. **에뮬레이터 문제였다**고 봐도 되겠다.
> 9/21 §5 의 "시작 쪽 ANR" 도 같은 결론이다.

### 임시 기록 6건을 직접 넣었다

사용자 요청. **앱 코드는 건드리지 않고** drift sqlite 에 직접 넣었다 —
"임시"라면 나중에 지울 코드가 남지 않는 쪽이 맞다.

| 날짜 | 타입 | 거리 | 시간 | 코스 |

| 09.20 (일) | 테마 | 5.21km | 35:37 | 남산 순환 2바퀴 |
| 09.17 (목) | 온라인 | 10.39km | 1:00:23 | 여의도 10K |

| 09.06 (일) | 테마 | 6.41km | 41:43 | 뚝섬→성수 |
| 08.30 (일) | 일반 | 4.66km | 28:15 | 올림픽공원 |

생성기는 `scratchpad/seed_runs.py`(레포에 안 넣었다). 서울 실제 좌표를 9m 간격
으로 리샘플하고, 구간마다 페이스를 흔들어 막대가 밋밋하지 않게 했다.
좌표마다 `t`(벽시계)와 `e`(달린 시간)를 실었고 09.22·09.17 에는 일시정지
(3분·4분)를 넣어 둘이 갈라지게 했다.

**adb 로 sqlite 를 밀어넣을 때 주의**: `adb shell cat > file` 은 바이너리를
깨뜨린다(CRLF 변환). `adb push` → `/data/local/tmp` → `run-as cp` 가 안전하다.
Git Bash 는 `/data/...` 를 Windows 경로로 바꾸므로 `MSYS_NO_PATHCONV=1` 이 필요하다.

## 6. 🔴 내 실수 — 빌드에 `env.json` 을 빠뜨렸다

오늘 만든 APK 들에 `--dart-define-from-file=env.json` 을 안 붙였다. Supabase
접속 정보가 **비어 있는 채로** 빌드됐다.

그 결과 세 가지가 어긋났다:

| | |
|---|---|
| ① | `pm clear` 후 로그인 화면이 아니라 홈이 떴다. 내가 "구글 로그인이 UI 없이 복원된 것 같다"고 **틀리게 설명했다** — 실제로는 `isConfigured == false` 라 로그인 관문이 통째로 꺼진 것(`splash_screen.dart` 51줄 `gateEnabled && isConfigured`) |
| ② | 가짜 기록이 서버에 올라갈 걱정이 없었다 — 올릴 데가 없었으니까 |
| ③ | **야외 검증에 구멍**이 생길 뻔했다. 오프라인에서 뛰고 돌아와 자동 업로드되는지가 `offline-handling.md` 의 핵심인데 테스트 자체가 불가능했다 |

`env.json` 을 넣어 릴리즈로 다시 빌드·설치했다. 로그인 화면이 떠서 설정이
들어간 걸 확인했고, `runearth.dev@gmail.com` 으로 로그인했다.

> **빌드 명령에 `--dart-define-from-file=env.json` 을 빼먹지 말 것.**
> 빠뜨려도 앱은 멀쩡히 켜지기 때문에 화면만 봐서는 모른다.

## 8. 야외 실기기 검증 (당일 밤, 노트8 릴리즈)

밤에 실제로 4건을 뛰었다 — 1.17km(10:06) · 1.01km(07:36) · 0.15km(02:16) ·
**5.14km(34:33)**. 배터리 100% → 89%(약 2시간, 러닝 34분 포함).

### 🟢 통과한 것

| | 결과 |
|---|---|
| **ANR** | **한 번도 안 났다.** 시작·달리는 중·종료 전부. dropbox 에 앱 기록 0건 — §4 의 에뮬레이터 ANR 은 **에뮬레이터 문제였다** |
| **사진 모드** | 실기기에서 동작. 야간 사진 위에 수치·경로·워터마크. 결정 ⑨(상단 어둠 0.65) 덕에 가로등 빛 위에서도 '일반' 뱃지가 읽혔다 — §2 의 **마지막 미검증 항목이 닫혔다** |
| **백그라운드 추적** | 34분이 끊김 없이 기록됨 |
| **서버 동기화** | 4건 전부 업로드 ('동기화 대기' 없음) |
| **구간별 페이스** | 1~5km + 자투리로 나왔다 |

### 🔴 GPS 거리가 35% 부풀었다

구간별 페이스에 **`3'47"`** 가 찍혔다. 평균이 `6'44"` 인데 한 구간만 엘리트
마라토너 페이스다. 화면 버그가 아니라 **데이터가 그렇게 들어온 것**이었다.

릴리즈 빌드라 DB 를 못 뽑아서 **디버그로 잠시 바꿔 깔고**(기록은 유지된다)
좌표를 직접 뜯었다. 원인이 둘이었다.

**① 화면을 끄면 안드로이드가 위치 갱신을 늦춘다.** 3초를 요청해도 실제로는
**8~11초** 간격으로 왔다(274구간 중 113개가 정확히 8초). 앱이 폰의 절전 예외
목록에 없어 제한 대상이었다. 시간대별로 보면 분명하다:

| 경과 | 좌표 간격 | 말이 안 되는 구간 |
|---|---|---|
| 0~4분(화면 켬) | 5~6초 | **0개** |
| 8~16분 | 9~11.6초 | 2개 |
| 20~30분 | 7~8초 | 16개(1,398m) |

> **사용자가 먼저 알아챘다** — "화면을 보고 있으면 안 튀는데 백그라운드로
> 돌 때 저렇게 되는 것 같다." 데이터가 정확히 그 말대로였다.

**② 간격이 벌어지면 GPS 흔들림이 한 번에 뭉쳐 들어온다.** 5.14km 기록에서
**25개 구간이 사람이 못 내는 속도**였다(최악: 7초에 126m = 시속 65km).
그 거리 합이 **1,785m — 총 거리의 35%**.

**③ 간격만이 원인은 아니다.** 간격이 5초로 촘촘했던 1.17km 기록에도 시속
53km 구간이 있었다. 밤에 건물·나무 근처에서 GPS 자체가 부정확했다.
그래서 절전 제외만으로는 부족하고 속도 필터가 함께 필요하다.

### 고친 것 (`ec2d944`)

사용자 결정으로 **둘 다** 넣었다.

- **속도 상한 6.0 m/s** 를 넘는 좌표는 **버린다**(`2'47"/km` — 마라톤 세계기록
  페이스 5.7 m/s 보다 빠르다). 앵커는 그대로 둬 다음 좌표가 제자리를 찾으면
  이어진다. 5.0~7.0 을 다 돌려보니 총거리가 4.16~4.46km 로 거의 안 변해
  경계에 민감하지 않다(8.0 부터 노이즈가 다시 샌다)
- **30초 넘게 끊겼다 돌아온 좌표는 속도 검사를 건너뛴다.** 멀리 떨어져 있는 게
  정상이라 속도로 재면 앵커가 영영 안 움직인다. RESUME 과 같이 앵커로만 쓰고
  거리에 더하지 않는다
- **배터리 최적화 제외 요청** — 시작 때 사전 안내 → 시스템 다이얼로그.
  거부해도 러닝은 막지 않는다(알림 권한과 같은 원칙).
  매니페스트에 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 추가

'버리기' 와 '거리만 상한까지 깎기' 를 둘 다 돌려보고 **버리기로 정했다**
(사용자 결정). 오늘 기록에 적용하면:

| 기록 | 전 | 후 |
|---|---|---|
| 1.17km | 1.17 | **1.05** |
| 1.01km | 1.01 | **0.75** |
| 5.14km | 5.14 | **3.52** |
| 구간별 페이스 3km | `3'46"` | **`5'25"`** |

### ⚠️ 과다 계상이 아직 남아 있다

사용자가 **"실제로는 1km 가 안 됐다"** 고 한 기록이 필터를 거쳐도 **1.05km** 다.
추정치 하나에 맞춰 숫자를 더 조이면 과교정 위험이 있어 그대로 뒀다.

조일 곳은 둘 — **최소 이동거리**(지금 5m)와 **속도 상한**(지금 6.0 m/s).
조합별 결과는 이미 뽑아뒀다(예: 10m·5.0 m/s 면 1.17km 런이 1.00km).

> **다음 검증은 '거리를 아는 코스'로 해야 한다.** 트랙 몇 바퀴, 아파트 단지
> 한 바퀴처럼 실제 거리를 아는 곳이어야 숫자를 맞출 수 있다. 지금은 비교할
> 기준이 없어서 더 못 조인다.

### 알게 된 것

- **릴리즈 빌드로는 진단을 못 한다.** `run-as` 가 막혀 DB 를 못 뽑는다.
  GPS 정확도를 계속 볼 동안은 **디버그를 깔아두는 게 낫다**(배터리 수치는
  이미 쟀다)
- **`Position.accuracy` 를 저장하지 않는다.** 정확도로 거르는 게 더 정석인데
  기록이 없어 임계값을 못 정했다. 속도 필터를 고른 이유이기도 하다 —
  그건 오늘 데이터로 검증할 수 있었다
- 칼로리가 전부 0 이다. 실기록·시드 가릴 것 없이 `🔥 0` 으로 나온다
