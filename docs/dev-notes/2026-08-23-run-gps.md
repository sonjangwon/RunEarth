# 08.23 — 달리기 GPS 실동작 (추적·거리·경로 저장)

## 📅 오늘 한 일 요약 :

**어제 만든 "UI만 있던 달리기 화면"에 실제 GPS 추적을 붙여서, 달리면 거리·페이스·시간이 실시간 계산되고 경로가 그려지고 종료 시 로컬 DB에 저장돼 기록 탭에 자동으로 뜨는 것까지 완성했다. 러닝 중 지도는 "캔버스 라인"으로 먼저 붙였다가 Google Map으로 방향을 바꾸기로 결정했고, 키 발급은 내일 이어서 하기로 했다.**

### 1. 파악 & 결정 (물어보고 승인받음)

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| **러닝 중 지도** | 캔버스 폴리라인 → **Google Map으로 전환 결정** | 모바일 네이티브 지도는 **무료·무제한** 확인(아래 결정사항 참고) |
| **추적 범위** | 포그라운드 먼저 | 백그라운드는 실기기 테스트 필요 → 별도 단위 |
| **경로 저장** | `route` 필드 추가 | 대표 이미지 재생성·상세 경로에 좌표 필요 |
| **칼로리** | 미표시(`-- kcal`) 보류 | 정확 계산엔 몸무게 필요한데 입력 수단 없음 |

### 결정사항 / 고려사항

1. **지도 SDK : Google Map (MVP) — 러닝 중 실지도 표시로 방향 전환**
당초 "캔버스 라인(키 불필요)"으로 먼저 붙였으나, 러닝 중 주변 도로/동네가 안 보이는 게 걸려서 Google Map으로 전환하기로 함. 확인 결과 **`google_maps_flutter`는 네이티브 SDK("Mobile Native Dynamic Maps")를 쓰고, 이건 무료·무제한**(공식 문서: "all mobile usage of the Maps SDK for Android is unlimited"). 블로그들이 말하는 "월 1만회 무료/$7"는 웹 지도 얘기라 우리와 무관. 단 키 발급엔 결제 계정(카드) 등록 필요, 유료 API(Directions·Places·Roads)는 안 켜면 과금 없음.
2. **커버 이미지(종료 후 대표 이미지)는 지도 없이 네온 라인만** 유지 — 문서 확정 사항. 그래서 캔버스 렌더러는 Google Map 도입 후에도 커버 이미지용으로 계속 사용(러닝 중 화면만 GoogleMap으로 교체).
3. **GPS 추적 : 포그라운드 먼저 / 백그라운드는 별도 단위** — 추적·거리계산·저장 로직을 먼저 완성. 백그라운드(iOS Background Modes + Android Foreground Service, "항상 허용" 권한)는 실기기 테스트가 사실상 필수라 분리.
4. **경로 좌표(polyline) 저장 = `route` 필드 신규 추가** — 러닝 앱은 전체 트랙을 저장해야 나중에 경로 재렌더·상세 지도·GPX가 가능. 문서 Run 타입엔 없던 신규 필드라 승인받고 추가, drift 스키마 v2로 마이그레이션.
5. **칼로리는 몸무게가 있어야 계산 가능** — 러닝 칼로리 ≈ 체중×거리×1.036. 현재 앱에 체중 입력 수단이 없어 정확한 값을 못 냄 → 임시 추정값(65kg) 대신 **미표시(`- kcal`)로 보류**. 프로필/온보딩에 체중 입력이 생기면 계산 연결(기획 논의 필요).
6. **커버 이미지는 현재 로컬 파일 경로로 저장** — 서버 동기화 시 이 경로는 무의미하므로, 업로드 후 URL로 치환하는 처리가 향후 필요.

### 임시로 처리한 것 / 향후 반드시 염두에 둘 것

- **3-1. 칼로리 = 0 (미표시)** — `kcal`은 항상 `0` 반환, 화면 `-- kcal`, 저장값도 `0`.
  향후 몸무게 입력 생기면 `체중 × 거리 × 1.036` 식 연결(run-flow.md에 계산식 정의 없음 → 기획 논의).
- **3-2. 경로 라인이 일시정지 구간에서 안 끊김** — 거리 계산에선 정지구간 제외(정확)하나,
  `route`가 단일 배열이라 렌더 시 정지 전후가 직선으로 이어짐. 완벽히는 세그먼트 배열로 분리 저장/렌더 필요.
- **3-3. GPS 샘플링 = 5m 거리 필터만** — `LocationSettings(accuracy: best, distanceFilter: 5)`.
  run-flow.md 제안값 "3초 간격 + 5m"인데 시간 간격은 플랫폼 기본에 맡김. 필요 시 플랫폼별 interval 명시.
- **3-4. 백그라운드 추적 없음** — 백그라운드/화면 꺼짐 시 끊길 수 있음. run-flow 완료조건 #1 미충족.
  향후 별도 단위: iOS Background Modes + Android Foreground Service(+"항상 허용" UX). **실기기 필수.**
- **3-5. 위치 권한 = 포그라운드용만** — `WhenInUse`/`FINE·COARSE`만. 백그라운드 권한은 3-4와 함께.
- **3-6. 러닝 타입 고정 = 일반** — `RunTracker.build()`가 `RunType.normal` 시작. 테마/온라인 진입 주입 없음.
- **3-7. 커버 이미지 = 로컬 파일 절대경로** — 서버 동기화 시 무의미 → 업로드 후 URL 치환 필요.
  좌표 2점 미만이면 커버 미생성(`coverImageUrl=null`), 대체 이미지 정책은 run-flow.md [미확정].
- **3-8. 날씨/미세먼지 카드 = 하드코딩** — prerun 화면 더미. 외부 API 연동 별도.
- **3-9. gpsVerified = false 고정** — 서버 GPS 재검증은 MVP 이후(기능정의서).
