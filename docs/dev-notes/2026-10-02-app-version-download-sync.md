## 3. 내려받기 — 정한 것과 만든 것

### 정한 것 (사용자 승인, 정본 `offline-handling.md` §4-1)

| 항목 | 정책 |
|---|---|
| 언제 | 로그인 직후 + 앱 시작 + **재연결** |
| 범위 | 내 기록 **전부** (누적 계산이라 일부만 받으면 숫자가 틀린다) |
| 경로 | 함께 받는다 |
| 사진 | 미리 받지 않는다. 상세를 열 때 signed URL |
| 합치기 | **로컬에 없는 id 만 추가**, 있는 건 로컬 유지. 받은 행은 `synced_at` 채움 |

사용자 질문 *"모든 폰에서 동일한 경험이냐"* → **"조금 늦게 같아진다."** 실시간이
아니라 앱을 다시 켤 때 맞춰진다. 한계 4가지를 §4-1 에 적었다.

### 로그아웃하면 로컬을 비운다 — 코드를 보다 찾은 구멍
로컬 `runs` 에 **소유자 컬럼이 없고**, 로그아웃은 세션만 끊었다. 한 폰에서 A →
B 로 계정을 바꾸면 **B 에게 A 기록이 보이고, A 의 못 올린 기록이 B 로 업로드됐다**
(내려받기 이전부터 있던 문제). 내려받기가 붙으면 둘이 섞인다.

(가) 로그아웃 시 비우기 vs (나) `user_id` 컬럼 추가 → **(가)** (사용자 승인).
못 올린 기록이 있으면 업로드 1회(10초) 시도 → 남으면 **건수 경고 후 진행 가능**.
"막기" 대안도 제시했지만 사용자가 원래 안(경고)을 택했다. 탈퇴도 같다.

### 구현에서 걸린 것
- **사진 경로를 null 로 다시 올리면 서버 사진이 지워진다.** 내려받은 기록은
  `cover_image_url` 이 Storage 경로(`{uid}/{runId}.jpg`)라 로컬 파일이 없다.
  `uploadCoverPhoto` 가 "파일 없음 → null" 로 돌려주면 대표 이미지를 바꿔
  재업로드할 때 서버 경로가 지워진다. **경로를 그대로 돌려주게** 했다
- **"절대 경로가 아니면 서버 경로" 판정은 플랫폼마다 다르다.** 윈도우 테스트에서
  `/data/...` 가 상대 경로로 나와 테스트가 깨졌다. **UUID/파일명.jpg 정규식**으로 바꿨다
- Supabase API 는 한 번에 **1000행**에서 자른다 → 페이지를 넘겨 받는다
- 받는 중에 로그아웃하면 **앞 계정 기록이 비운 로컬에 다시 들어온다** → 넣기 직전에
  `currentUser.id` 를 다시 본다

단위 테스트 `test/run_download_test.dart` 7건(합치기 규칙 · 비우기 후 복원 · 경로 판정).
전체 37건 통과, analyze 0.

## 4. 노트8 실기기 검증 (디버그 빌드, env zip 검증 후 `install -r`)

`firstInstallTime=2026-08-30 22:22:46` 불변. 시작 전 `app_flutter` 전체를
**tar 로 백업**했다(scratchpad, 커밋 안 함).

| 확인 | 결과 |
|---|---|
| 프로필 버전 | ✅ `v1.0.0 (1)` |
| 첫 내려받기 | ✅ `서버 35건 중 새 기록 21건` — **예상(0건)과 달랐다** ↓ |
| 다른 기기 사진 | ✅ 9/26 2.61km(24:38) 상세에서 배경 사진 (사용자 눈으로 확인) |
| 로그아웃 → 재로그인 | ✅ 로컬 행·이미지 파일 삭제 → `서버 35건 중 새 기록 35건` |
| 못 올린 기록 경고 | ⬜ 미검증 — 오프라인으로 뛴 기록이 있어야 한다 |
| 다른 계정 분리 | ⬜ 미검증 — 두 번째 구글 계정이 필요하다 |

### 21건이 내려온 이유
노트8 은 서버 35건 중 14건만 갖고 있었다. 빠진 20건은 **9/21 에 검증 전
`pm clear` 로 로컬을 비운 결정** 때문이다(8/30~9/19 의 테스트·0km 기록 + 9/13
2.61km 실제 기록). 1건은 다른 기기의 9/26 사진 기록. **이 기능이 그때 있었으면
돌아왔을 기록들이다.** 홈이 53.6km/16회 → 60.4km/24회 가 됐다.

### 🔴 예상 밖 — 로그아웃이 6건을 지웠다
더미 1건만 사라질 줄 알았는데 **로컬 전용 행이 6건**이었다:
`seed_1`·`2`·`3`·`5`·`6` 과 10/01 더미. 시드들은 **`synced_at` 이 채워져 있는데
서버에는 없었다**(9/26 backlog 는 "서버에 있다" 고 적었었다. 원인 미상 —
다른 계정으로 올라갔거나 서버에서 지워졌을 수 있다). 경고는 `synced_at IS NULL`
만 세므로 **경고 없이 지워졌다.**

→ 사용자 결정 **"전부 올려"**. 백업에서 6행을 `synced_at = NULL` 로 되살리고
더미 사진 파일도 넣어 앱을 켜니 자동 업로드 → 재실행 시 `서버 41건 중 새 기록 0건`.
노트8 다시 60.4km. backlog '개발용 더미 데이터' 절에 반영했고, 10/01 노트의
"서버에는 없다" 줄에 ⛔ 를 달았다.

> **교훈**: 기기 DB 를 손으로 고칠 때 `synced_at` 을 채우는 건 "서버에 안 올린다"
> 는 스위치였지만, 이제는 **"로그아웃하면 사라진다"** 는 뜻도 된다(§4-1 한계에 적음).

### 기술 메모
- adb 가 중간에 2분 넘게 응답하지 않았다(탭·스크린샷 명령이 백그라운드로 밀림).
  ANR 은 없었다. 사용자가 폰을 직접 만지던 시점과 겹쳤을 수 있다 — **조작이
  겹치지 않게 사람 손으로 넘겼다**
- DB 반영은 10/01 과 같은 길: `/data/local/tmp` 경유 → `run-as sh -c 'cat > …'`
  → tmp 삭제. `MSYS_NO_PATHCONV=1` 필수
