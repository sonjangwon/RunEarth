## 3. 칼로리 — 80kg 가정, 저장하지 않고 화면에서 계산

10/01 §7 "칼로리·심박수·케이던스 `--` 가 의도인지" 의 답: **셋 다 의도였다.**
칼로리는 체중 입력이 없어서(`records.md`), 심박수·케이던스는 워치 데이터라서.
다만 후자의 규칙은 **코드 주석에만** 있었다 → `records.md`·`wearable-sync.md` 로 옮김.

사용자 결정 "체중 80 기준으로". 정한 것:

| 항목 | 결정 |
|---|---|
| 식 | `80 × km` 반올림 (달리기는 속도와 거의 무관하게 1kg·1km ≈ 1kcal) |
| 저장 | **안 한다.** `Run.displayKcal` 이 저장값(>0, 워치 등) 우선, 없으면 추정 |
| 추정 표시(`≈`) | 안 붙인다 |

**저장하지 않은 이유가 핵심이다.** 저장하면 서버에 올라간 41건을 다시 올려야 하고,
10/02 에 정한 내려받기 규칙("로컬에 있는 id 는 로컬 유지")이 **기기마다 다른 숫자를
남긴다.** 화면에서 계산하면 체중 입력이 생겨도 상수 하나만 바꾼다.

실기기: 2.56km → 205, 0.72km → 58, 2.61km → 209.

## 4. 날씨 — 기상청

### 정한 것 (사용자 결정)

| 항목 | 결정 | 이유 |
|---|---|---|
| `http` 패키지 | 추가 | 문서에 없는 패키지라 물었다 |
| 체감온도 | **안 쓴다** | ⚠️ 내가 낡은 backlog 줄("체감 26°")만 보고 물었다. **9/27 에 이미 Figma 대로 뺐다** |
| 날씨 상태(맑음/흐림) | 초단기예보를 **한 번 더** 부른다 | 초단기실황에는 비·눈(PTY)만 있고 하늘상태(SKY)가 없다 |
| 재사용 | **다음 자료 발표 시각까지**(대략 매시 45분) | 사용자가 "30분 → 1시간" 을 물었다. 고정 1시간이면 최대 2시간 묵은 값이 보여 대안 제시 → 채택 |
| 위치를 모를 때 | "불러오지 못했어요" — **서울로 대신하지 않는다** | 가짜 값 금지 |
| 출처 표시 | **프로필 하단 버전 아래** | 카드가 좁다. 공공누리 1유형(저작자표시) 의무 |

### 기술 메모
- 위경도 → 격자(nx, ny)는 기상청 공개 LCC 식. 서울시청 (60, 127), 부산시청 (98, 76) 테스트
- **발표 시각은 KST 로 계산한다** — `DateTime.now().toUtc() + 9h`. 기기 시간대가 달라도 맞다
- 키 오류는 **HTTP 200 + XML** 로 온다 → `jsonDecode` 실패로 잡힌다
- **예외 메시지에 요청 URL(=인증키)이 들어갈 수 있어** 로그엔 예외 타입만 남긴다.
  `HttpStatusError` 는 URL 을 안 담게 따로 만들었다
- 위치는 GPS 를 새로 잡지 않고 **기기의 마지막 위치**(출발 전 지도와 같은 값)

## 5. 미세먼지 — 에어코리아

### 정한 것 (사용자 결정)
- **PM10** 을 보인다 — 카드 제목 '미세먼지', Figma 게이지 상한 150 = PM10 '매우나쁨' 경계
- **단계는 숫자에서 계산** — API 의 `pm10Grade` 는 24시간 평균이라 1시간 숫자와 어긋난다

### 기술 메모
- 위경도 → TM 중부원점(GRS80, 가산 200000/500000). **실제 API 로 먼저 검증하고 포팅했다**
  — 서울시청 → 중구 측정소 0.5km, 부산시청 → 연산동 0.3km
- 측정소는 **격자가 바뀔 때만** 다시 찾는다. 평소엔 측정값 1건 — 한도가 **일 500건**이다
- 가장 가까운 측정소가 점검(`-`)이면 두 번째
- 에어코리아는 자정을 **`24:00`** 으로 적는다 → 다음 날 0시로 파싱
- 측정소 API 가 첫 호출에 **15초 넘게 무응답**이었다 → 타임아웃 10초
- 테스트에서 `http.Response(String)` 에 한글을 넣으면 latin1 인코딩으로 터진다 →
  `Response.bytes(utf8.encode(...))`. 앱 코드 문제가 아니었다

### 🔴 비밀값이 어긋나 매일 조용히 403 이 날 뻔했다
예약 경로 dry-run 이 `403 forbidden`. Vault 값 길이를 재보니 **7** — 안내문의
자리표시 `'여기에_비밀값'` 이 그대로 들어가 있었다. 처음 `= '여기에_비밀값'` 비교는
`false` 가 나와 놓칠 뻔했다(문자가 미세하게 달랐던 것으로 보인다). **길이로 재서 잡았다.**
고친 뒤 예약과 같은 경로로 `200 {"dry":true,"targets":0}`.

> **교훈**: 사람이 붙여넣는 비밀값은 **값을 보지 않고 확인할 수 있는 성질**(길이)로
> 검증한다. 그리고 "단독 호출이 됐다" 가 아니라 **"예약이 실제로 쓰는 경로로 됐다"**
> 를 확인해야 한다 — 4단계 PowerShell 호출은 통과했지만 예약 경로는 막혀 있었다.
> 확인 절차를 `supabase/README.md` 에 적었다.
