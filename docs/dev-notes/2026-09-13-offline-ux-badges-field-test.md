## 0. 시작 시점 상태

9/11 세션 이후 2일. 서버 연동(users·runs 업로드)은 붙었으나 화면 곳곳에 샘플
데이터가 남아 **앱이 거짓 정보를 보여주는** 상태였다. 프로필 통계는
`247.3km / 98h / 38회` 고정값이라 홈(실데이터)과 숫자가 달랐고, 배지는
누적 0.3km인데 인천(27km)·전주(194.3km) 도착을 획득했다고 표시하고 있었다.

그리고 **야외 GPS 검증은 여전히 0회** — 거리·페이스가 실제로 맞는지 아무도
모르는 채로 서버 업로드만 돌아가고 있었다(9/11 노트 §3-1의 최우선 항목).

## 1. 오늘 완성한 것 (커밋 5개, 17 files +344/-46)

### 1-A. 프로필 통계 실데이터 + 홈 CTA — 커밋 `7fb353c`

`_StatsRow` 를 `ConsumerWidget` 으로 바꿔 홈과 **같은** `homeStatsProvider` 를
구독한다. 총 시간은 `durationLabel`(`0h 2m`)로 통일 — 기존 `98h` 표기는 분이
잘렸다. 샘플 상수 4개 삭제.

비어 있던 홈 '지금 달리기 시작' CTA 를 `StatefulNavigationShell.of(context)
.goBranch(1)` 로 달리기 탭에 연결(하단 탭바와 같은 방식이라 탭 상태 보존).
러닝 타입 '일반' 지정은 `RunType` 이 아직 고정값이라 제외.

### 1-B. 전역 오프라인 배너 + 재연결 자동 동기화 — 커밋 `25ecb84`

**신규 패키지** `connectivity_plus: ^7.3.1` (승인받음).

- `lib/services/connectivity/connectivity_providers.dart` — `isOnlineProvider`.
  판정 전/실패 시 **온라인으로 본다**(앱 켤 때 배너가 번쩍이는 게 더 나쁘다).
- `lib/core/widgets/offline_banner.dart` — 상단 얇은 띠. `MaterialApp.builder`
  에서 감싸 shell 밖의 스플래시·로그인까지 덮는다(로그인이야말로 네트워크가
  필요한 화면). 온라인이면 `child` 를 그대로 반환해 평상시 레이아웃을 안 건드린다.
- `syncOnReconnectProvider` — 오프라인→온라인 **전환 순간에만** `syncNow()`.

> ⚠️ 한계: `connectivity_plus` 는 인터페이스 연결만 알고 실제 도달성은 모른다
> (와이파이 잡혔는데 공유기가 끊긴 경우 온라인으로 보고). 재연결 신호는
> "지금 한번 올려봐" 힌트일 뿐이고 실패하면 기존 재시도 타이머가 받아준다.

### 1-C. 기록 카드 '동기화 대기' 표시 — 커밋 `155c463`

DAO 에 `watchUnsyncedIds()` 추가 → `pendingSyncRunIdsProvider` → 카드가
자기 id 가 명단에 있으면 무채색 딱지를 붙인다.

**`Run` 모델에 `syncedAt` 을 넣지 않은 이유**: `records.md` §3 에 이미 정의된
대표 이미지 수정이 `upsertRun` 을 타면, 모델에 실린 옛 `syncedAt` 이 함께
덮어써져 **수정본이 서버에 영영 반영되지 않는다**. id 명단만 따로 흘려보낸다.

`offline-handling.md` §2-B 는 결과 화면(RunDetailView)을 지정하나 그 화면이
아직 없어 기록 카드에 먼저 적용. 두 문서에 근거를 남겼다.

### 1-D. 스플래시 무한 대기 차단 — 커밋 `9527608`

`_boot()` 에 예외 처리가 없어, 예외가 나면 라우팅에 도달하지 못하고 스피너
화면에 **영구히 갇혔다**. 스플래시는 빠져나올 수단이 없는 화면이라 복구 불가.

드러난 경로: `--dart-define-from-file=env.json` 없이 실행 → Supabase 미초기화
→ `currentSession()` 이 던짐 → 무한 대기.

두 층으로 막았다. ① `isConfigured` 가드 3곳 추가(`currentSession`,
`authStateChangesProvider`, `sessionDisplayName`) — 나머지 호출부는 이미
가드가 있었고 이 셋만 빠져 있었다. ② `_boot()` 에 fail-safe `try/catch`.

검증에서 **catch 로그가 찍히지 않았다** = 가드가 예외를 아예 없앴다는 뜻.
try/catch 는 앞으로의 다른 원인에 대비한 안전망으로 남는다.

### 1-E. 여정 마일스톤 배지 실데이터 — 커밋 `b60c7f6`

마스터 경로 **22개 도시**(국내 4 + 해외 G20 수도 18)에서 배지를 생성하고
`journeyProgressProvider.absolutePositionKm >= city.cumulativeKm` 로 판정.
서버도 새 필드도 필요 없는 파생값이라 저장하지 않고 매번 계산한다
(`User.streak` 을 서버에 두지 않은 것과 같은 이유).

기준값을 홈 여정과 **같은** provider 로 쓴 이유: 시작 도시가 서울이 아니게
되면(journey.md §2) 두 화면이 어긋난다.

테마 코스·월별 마라톤 배지는 제외 — 두 기능 자체가 없어 지급 조건을 판정할
데이터가 존재하지 않는다. 고정값 `N / 11` 도 `badges.md` §4 가 요구하는
동적 계산으로 바뀌었다.

이로써 **프로필 탭에서 샘플 데이터가 완전히 사라졌다.**

## 2. ⭐ 첫 야외 GPS 검증 (가장 중요)

릴리즈 APK 를 실기기(갤럭시 노트8, Android 9)에 설치하고 실제로 뛰었다.

```
flutter build apk --release --dart-define-from-file=env.json
adb install -r build/app/outputs/flutter-apk/app-release.apk
```

> 릴리즈도 **debug 키로 서명**(`build.gradle.kts` 의 TODO)이라 SHA-1 이 debug 와
> 같아 구글 로그인·지도 키 제한을 그대로 통과한다. 덕분에 지금은 APK 파일
> 전달 방식의 배포까지는 된다. **Play 스토어는 불가** — 별도 릴리즈 키스토어를
> 만들고 그 지문을 Google Cloud 에 등록해야 한다.

### 결과: 거리·페이스 계산이 맞다 🟢

| 거리 | 페이스 | 시간 |
|---|---|---|
| 0.49 km | 11'03" | 05:22 |
| **2.61 km** | **7'41"** | **20:02** |
| 0.15 km | 14'12" | 02:04 |
| 0 km ×2 | --'--" | 01:37 / 00:00 |

2.61km 로 검산: `1202초 ÷ 2.61km = 460.5초/km = 7분 40.5초` → 표시 `7'41"` ✓
짧은 기록의 1~2초 오차는 화면에 반올림된 거리로 역산해서 생기는 것.

**프로젝트에서 가장 오래된 미지수가 해소됐다.** 지도·경로 렌더·저장·업로드도
전부 실제로 동작했다(8:28 스크린샷에 안양천 경로가 네온그린으로 정상 렌더).

### Supabase 확인

대시보드 `runs` 테이블에 09.13 기록 **5건 모두** 존재.

anon 키로는 조회 시 `[]` 가 돌아온다 = **RLS 가 제대로 걸려 있다**.
(대시보드 SQL Editor 는 `postgres` 권한이라 RLS 를 우회해 조회할 수 있다.)

### `route` 좌표 보존 확인 + 샘플링 설정 실측 검증 🟢

```sql
select id, date, km, dur, jsonb_typeof(route) as 타입,
       case when jsonb_typeof(route)='array'
            then jsonb_array_length(route) end as 좌표수
from runs order by created_at desc;
```

| 기록 | 좌표수 | 좌표당 간격 |
|---|---|---|
| **2.61km / 20:02** | **383** | 3.1초 · 6.8m |
| 0.49km / 05:22 | 74 | 4.4초 · 6.6m |
| 0.15km / 02:04 | 18 | 6.9초 · 8.3m |

- `타입` 은 **전 행 `array`**. 대시보드 Table Editor 에서 표기가 두 가지로
  보였던 것(`"lat":` vs `"lat": `)은 **렌더링 차이일 뿐 데이터 이상이 아니다.**
- 좌표가 목동·양평동 일대(37.515~/126.873~) — 실제 뛴 위치와 일치.
  09-11 행들은 종로 좌표(37.5679/126.9801) = 에뮬레이터 기본 위치.
- **`run-flow.md` §6 의 샘플링 제안값("3초 간격 + 5m 필터")이 실측으로
  검증됐다** — 2.61km 기록 실측 3.1초 / 6.8m. 설정대로 동작한다.
- 383점이면 경로 렌더에 충분하다. 9/11 결정("커버 이미지는 올리지 않고
  `route` 좌표만 있으면 어디서든 다시 그린다")이 성립함이 확인됐다.

## 3. ⚠️ 발견된 문제 (전부 미해결)

### 3-1. 진행 중인 러닝이 통째로 사라진다 ← 최우선

8:38 스크린샷에 **0.24km / 03:33** 로 기록 중이던 세션이, 3분 뒤 8:41 기록
목록에도 서버에도 **없다**.

`run_screen.dart` `_onStopConfirmed()` 를 보면 저장은 **STOP 확인을 눌러야만**
일어난다. 그 전에 탭을 옮기거나 앱을 내리면 기록이 통째로 날아간다.
"기록은 잃지 않는다"가 상위 원칙인데 **진행 중 러닝은 전혀 보호되지 않는다.**

`run-flow.md` §7 의 "백그라운드 중 OS 강제 종료 시 복구 방법 `[미확정]`" 과
같은 뿌리. 복구 방식(진행 중 세션을 주기적으로 로컬에 쓸지, 앱 시작 시
이어하기를 물을지)은 **결정 필요**.

### 3-2. `GPS 기록 중` 인데 경로가 안 그려지는 경우

8:38 스크린샷: 상태는 초록 `● GPS 기록 중`, 거리 0.24km 인데 **지도에 경로선이
없다**. 페이스 14'32"/km(걷기보다 느림) → 제자리에서 GPS 노이즈가 5m 필터를
넘으며 거리만 쌓인 정황. 좌표가 한 점에 뭉쳐 선이 파란 마커에 가려진 것으로 추정.

즉 "신호가 없다"가 아니라 **"잡히긴 했는데 품질이 나쁘다"**. 지금 UI 는 이 둘을
구분해 알려주지 못한다. 참고로 `🛰 GPS 신호를 기다리는 중…` 문구의 실제 조건은
`route.length < 2` 라서 **신호와 무관**하고, START 전에는 절대 사라지지 않는다
(사용자가 폰 고장을 의심하게 만든다).

**서버 데이터로 확인된 증거**: `run_1789297203613307`(09.13, 0km, `01:37`)의
좌표가 **단 1개**다. 1분 37초 동안 첫 점 이후 아무것도 안 들어왔다는 뜻.
같은 날 야외 기록인데도 그렇다(08.30 기록들이 전부 1개인 건 실내라 예상된 것).

**그런데 원인을 사후에 판별할 수 없다** — ① 신호를 못 잡아 업데이트가 없었는지
② 제자리에 서 있어 5m 필터를 한 번도 못 넘었는지가 똑같이 "좌표 1개"로 남는다.
`Position.accuracy` 나 마지막 수신 시각을 **아무 데도 저장하지 않기 때문**이다.
고칠 때 이 값들을 남기는 것까지 함께 고려할 것.

### 3-3. 기록에서 경로 이미지를 볼 수 없다

경로 이미지는 저장 시 생성돼 `coverImageUrl` 에 들어가 있는데, **기록 상세
화면이 없어** 볼 방법이 없다. 오늘 2.61km 경로가 이미 저장돼 있으니 화면만
만들면 바로 보인다. `offline-handling.md` §2-B 의 '동기화 대기' 배지도 원래
여기 붙어야 한다.

### 3-4. 0km 기록이 목록을 어지럽힌다

오늘 5건 중 3건이 0km(눌렀다 만 것). 다른 러닝앱은 저장하지 않는 듯.
다만 `records.md` §4 에 **"기록 삭제 불가 — 영구 보존"** 이 못박혀 있어
저장을 막을지/숨길지는 문서 정책과 충돌 → **결정 필요**.

### 3-5. 동기화가 업로드 전용이다

서버 13건 vs 폰 10건. 차이 3건은 에뮬레이터에서 올린 테스트 기록
(`run_1788099047068836`·`...063499516`·`...099700000186`). **앱이 서버에서
내려받지 않는다** → 재설치·기기 변경 시 서버에 멀쩡히 있는 기록을 복원 못 한다.
`offline-handling.md` §5 가 상정한 것보다 공백이 크다.

> 위 3건은 9/11 노트에서 "실제 기록으로 보존"했다고 적힌 것들인데, 실제로는
> 에뮬 테스트였다. 사용자 확인 후 **서버에서 지우지 않고 그대로 두기로** 결정.

### 3-6. 백그라운드 추적 미검증 (아마 깨져 있음)

오늘 러닝은 **화면을 계속 켜둔 채** 진행했다. `run_tracker.dart` 는 일반
`LocationSettings` 를 쓰고 `AndroidSettings` + `foregroundNotificationConfig` 가
없다. 매니페스트에도 `FOREGROUND_SERVICE`/`ACCESS_BACKGROUND_LOCATION` 이 없다.
Android 8+ 는 백그라운드 위치를 시간당 몇 번으로 제한하므로 **화면을 끄면
거리가 안 쌓일 가능성이 높다.** 실측 필요.

### 3-7. 이전 노트에서 이어지는 것

칼로리(`0kcal` 로 실데이터 확인됨 — 몸무게 입력 필요), 일시정지 세그먼트
미분리, 날씨/미세먼지 하드코딩, RunType 고정, `gpsVerified=false`, iOS 키(Mac),
여정 히어로 이미지 Unsplash 임시, 프로필 설정 메뉴 7개 전부 무동작.
