### 1. 개요

실제 마라톤은 시간·장소·비용 부담이 크다. 지정된 지역의 고정 경로를
사용자가 원하는 시간에 자유롭게 뛰고, 기록으로 순위를 매기는 비동기 경쟁 콘텐츠.

### 2. 사용자 시나리오

- 사용자는 "콘텐츠 > 온라인 마라톤" 탭에서 진행 중인 챌린지 목록을 본다.
- 관심 있는 챌린지를 눌러 코스 상세(경로, 거리, 참여자 수, 현재 랭킹)를 확인한다.
- "참여하기"를 누르면 해당 코스가 홈 화면 "현재 여정"으로 등록된다.
  → 이 시점에 **푸시 알림 소프트 opt-in 모달**이 노출된다 (`push-notifications.md` 3번 참조)
- 사용자가 해당 경로를 뛰면 GPS 기록이 자동으로 챌린지 기록으로 인정 여부가 판정된다.
- 챌린지 종료일에 순위가 확정되고, 보상(포인트/메달)이 지급된다.

#### 4-1. GPS 경로 인정 로직 (엄격 매칭 — 확정)

1. 러닝 종료 시, 수집된 GPS 트랙 포인트들을 코스의 지정 경로(polyline)와 대조한다.
2. 각 트랙 포인트가 경로로부터 **반경 30m 이내**에 위치하면 "온-코스" 포인트로 판정한다.
3. 전체 트랙 포인트 중 **90% 이상이 온-코스**여야 완주로 인정한다.
4. 추가로, 총 이동 거리가 **코스 목표 거리의 100% 이상**이어야 한다 (경로 근처를
   왔다갔다만 하고 거리를 채우지 않는 부정 케이스 방지).
5. 1~4 중 하나라도 미충족 시 → 러닝 기록은 "일반 러닝"으로는 정상 저장되지만,
   마라톤 챌린지 랭킹에는 반영되지 않는다. 종료 화면에 "코스 인정 조건을
   충족하지 못했어요" 안내 문구 노출.

> ⚠️ 위 수치(30m, 90%, 100%)는 개발 착수를 위한 **초기 제안값**입니다.
> 실제 기기별 GPS 오차 테스트 후 조정이 필요할 수 있어 조정 여지를 열어둡니다.
> 다만 이 값이 없으면 로직 구현 자체가 불가능하므로, 확정값이 나오기 전까지
> 이 수치를 기준으로 개발을 진행합니다.

#### 4-2. 재도전 시 랭킹 반영 정책 (확정)

- 같은 챌린지를 여러 번 시도해도 **모든 시도 기록은 "기록" 탭에 개별 저장**된다.
- 마라톤 챌린지 랭킹에는 **해당 사용자의 최고 기록(가장 빠른 기록)만** 반영된다.
- 최고 기록이 갱신될 때마다 랭킹 재계산 (5분 배치 갱신 주기에 포함)

### 5. 인터랙션 / 마이크로카피

- 참여하기 탭 → 확인 바텀시트 ("이 코스에 참여하시겠어요? 참여 후에도 언제든 뛸 수 있어요")
  → 확인 시 **푸시 알림 소프트 opt-in 모달** 노출 (최초 참가 시 1회, `push-notifications.md` 참조)
- 참여 중 카드 탭 → 코스 상세로 이동, 현재 내 랭킹(최고 기록 기준) 하이라이트
- 러닝 종료 시 코스 인정 실패: "코스 인정 조건을 충족하지 못했어요. 기록은 저장됐지만 챌린지 랭킹에는 반영되지 않아요"
- 순위 반영 지연 안내: "곧 순위에 반영돼요 (최대 5분 소요)"

### 6. 데이터 요구사항 (개발자 확인 필요 영역)

**확정된 프론트엔드 타입** (`RUNNA_KR_기능정의서.md` 6-6 참조):

```typescript
type Marathon = {
  name: string;
  distance: string;
  course: string;
  location: string;
  dday: string;
  prize: string;
  prizeEmoji: string;
  joined: boolean;
  ended: boolean;
  participants: string;
  myRank: string | null;
  myTime: string | null;   // 최고 기록 기준
  img: string;
};
```

**신규 확정 사항**

- 코스 원본 데이터: 경로 좌표(polyline), 경로 인정 반경(30m 고정값) — 코스별로
  다르게 줄 수도 있으니 **[미확정]** 코스마다 다른 반경이 필요한지, 전역 고정값으로
  충분한지는 추후 논의
- 매칭 판정 로직은 **클라이언트(러닝 종료 직후) vs 서버(업로드 후 서버에서 재검증)**
  중 어디서 수행할지 → **[미확정]** 부정 방지 관점에서는 서버 검증 권장하나 개발
  리소스에 따라 클라이언트 우선 판정 + 서버 최종 검증 하이브리드도 가능
- 랭킹/참가자 수: **5분 배치**로 서버에서 재계산 후 캐시된 값을 프론트에 제공
- 최고 기록 갱신 로직: 신규 기록 업로드 시 기존 `myTime`과 비교해 더 빠르면 갱신

### 7. 엣지 케이스

- ✅ 같은 코스 재도전 → 최고 기록만 랭킹 반영 (확정, 4-2 참조)
- ✅ 챌린지 취소/변경 시 → 푸시 알림으로 안내 (확정, `push-notifications.md` 참조)
- GPS 신호 불안정으로 트랙이 끊긴 경우 → 90% 기준 충족 여부로 자연스럽게 처리되나,
  "신호 불안정으로 인정되지 않았어요" 같은 별도 안내가 필요할지는 **[미확정]**
- 참가 중 사용자가 앱을 삭제/재설치한 경우 참가 상태 복구 방식 — **[미확정]**

### 8. 완료 조건 (Acceptance Criteria)

- [ ] 콘텐츠 탭에서 진행 중/종료 챌린지 목록이 카드로 노출된다
- [ ] 카드에 코스 위치, 참여자 수, 현재 1위(최고 기록) 기록이 표시된다
- [ ] 참여 시 홈 화면 "현재 여정"에 반영되고, 푸시 opt-in 모달이 노출된다
- [ ] 러닝 종료 시 GPS 경로 인정 로직(30m/90%/100%)에 따라 랭킹 반영 여부가 결정된다
- [ ] 같은 코스 재도전 시 최고 기록만 랭킹에 반영된다
- [ ] 랭킹/참가자 수는 5분 이내로 갱신된다
- [ ] 챌린지 취소/변경 시 opt-in한 사용자에게 푸시 알림이 발송된다
- [ ] 종료된 챌린지는 결과(순위/보상)가 표시된다
