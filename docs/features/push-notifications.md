## 푸시 알림 시스템 (전역 기능)

**최종 수정일**: 2026-08-15
**상태**: 🟡 1차 스코프(챌린지 취소/변경) 정의 완료 · 나머지 알림 종류는 확장 예정
**담당**: 기획/디자인 - OOO / 개발 - OOO
**트리거**: 온라인 마라톤 로직 정의 중 "챌린지 취소/변경 안내"에서 파생 — 앱 전역에서
재사용할 인프라이므로 별도 기능으로 분리

### 1. 개요

특정 화면 하나에 종속되지 않는 전역 푸시 알림 인프라. 온라인 마라톤 챌린지
취소/변경 안내를 첫 사용처로 확정하고, 다른 알림 종류는 이 인프라 위에서
추후 확장한다. 시스템 권한을 억지로 요청하지 않고, **자체 UI로 먼저 필요성을
설명한 뒤 동의를 유도하는 소프트 opt-in 패턴**을 사용한다.

### 2. 사용자 시나리오

- 사용자가 온라인 마라톤에 최초로 참가("참여하기" 확인) → 참가 처리 직후
  **소프트 opt-in 모달** 노출
- 모달에서 "켤게요" 선택 → OS 시스템 알림 권한 요청 다이얼로그 호출
  - 시스템 권한 허용 → 알림 활성화
  - 시스템 권한 거부 → 비활성 상태 유지, 이후 설정 메뉴에서 안내로 유도 가능
- 모달에서 "다음에 할게요" 선택 → 모달만 닫힘, 이후 재노출 정책은 **[미확정]**
  (매 챌린지 참가마다 다시 물어볼지, 최초 1회만 물어볼지)
- 알림 켠 사용자 → 참가 중인 챌린지가 취소/변경되면 푸시 알림 수신

### 3. 화면 구성

**소프트 opt-in 모달** (온라인 마라톤 최초 참가 시 노출)

| 요소 | 내용 |
|---|---|
| 타이틀 | 예: "챌린지 소식을 놓치지 마세요" |
| 본문 | 예: "챌린지 취소나 일정 변경이 생기면 바로 알려드릴게요" |
| 주 버튼 | "알림 받기" (초록, 주요 액션) |
| 보조 버튼 | "다음에 할게요" (텍스트 링크) |

> 이건 OS 권한 다이얼로그가 아니라 **자체 제작 UI**입니다 — 여기서 "알림 받기"를
> 눌러야 그다음에 진짜 시스템 권한 요청이 뜨는 2단계 구조입니다. 시스템 다이얼로그를
> 바로 띄우면 사용자가 이유도 모른 채 거부할 확률이 높아서, 이 소프트 단계로
> 동의율을 올리는 게 목적입니다.

### 4. 컴포넌트 & 상태 정의

| 상태 | 조건 | UI 처리 |
|---|---|---|
| 미노출 | 온라인 마라톤 미참가 | 모달 안 뜸 |
| 소프트 opt-in 노출 | 최초 참가 확정 직후 | 모달 표시 |
| 시스템 권한 허용됨 | 사용자가 OS 다이얼로그에서 허용 | 알림 활성 상태로 전환, 설정 메뉴에도 반영 |
| 시스템 권한 거부됨 | OS 다이얼로그에서 거부 or 이후 기기 설정에서 끔 | 알림 비활성, 프로필 설정 메뉴에서 "알림이 꺼져 있어요" 안내 노출 |
| 알림 거절(소프트) | "다음에 할게요" 선택 | 모달 닫힘, 시스템 권한 요청 안 함 |

### 5. 인터랙션 / 마이크로카피

- 소프트 opt-in 타이틀/본문: 위 3번 표 참조
- 시스템 권한 거부 후 설정 메뉴 안내 문구(예): "챌린지 소식을 받으려면 기기 설정에서 알림을 켜주세요"

### 6. 데이터 요구사항 (개발자 확인 필요 영역)

```typescript
type NotificationType =
  | "challenge_update"   // 챌린지 취소/변경 (1차 스코프, 확정)
  | "streak_reminder"    // [미확정] 향후 확장 후보
  | "rank_overtaken";    // [미확정] 향후 확장 후보

type NotificationPreference = {
  userId: string;
  systemPermissionGranted: boolean;  // OS 레벨 권한 상태
  softOptInShownAt: string | null;   // 소프트 모달 최초 노출 시각
  softOptInDismissedCount: number;   // "다음에 할게요" 선택 횟수 — 재노출 정책 판단용
};
```

- 푸시 발송 트리거: 챌린지 관리자가 대회 정보를 취소/변경할 때 서버에서
  해당 챌린지 참가자 중 `systemPermissionGranted: true`인 사용자에게 발송
- 재노출 정책(같은 사용자에게 소프트 모달을 몇 번까지 다시 보여줄지) →
  **[미확정] 마케팅팀/기획 논의 필요** — 너무 자주 물으면 피로도 유발
- 알림 발송 인프라(FCM/APNs 등)는 온라인 마라톤뿐 아니라 향후 다른 알림
  종류에도 재사용되므로, 개발 시 특정 기능에 종속되지 않게 공용 서비스로 설계 권장

### 7. 엣지 케이스

- 사용자가 여러 챌린지에 동시 참가 중인데 그중 하나만 취소된 경우 → 해당
  챌린지 이름을 명시한 알림이어야 함 (모호한 "챌린지가 취소됐어요" 금지)
- 시스템 권한을 나중에 기기 설정에서 직접 켠 경우 → 앱이 이 변경을 감지해서
  `systemPermissionGranted` 값을 동기화해야 함
- 소프트 모달을 계속 거절하는 사용자에게 무한정 다시 묻지 않도록 상한 필요 →
  **[미확정]** (예: 최대 2회까지만)

### 8. 완료 조건 (Acceptance Criteria)

- [ ] 온라인 마라톤 최초 참가 시 소프트 opt-in 모달이 노출된다
- [ ] "알림 받기" 선택 시 OS 시스템 권한 다이얼로그가 호출된다
- [ ] 시스템 권한이 허용된 사용자만 실제 푸시를 수신한다
- [ ] 참가 중인 챌린지가 취소/변경되면 opt-in한 참가자에게 챌린지명이 포함된 푸시가 발송된다
- [ ] 권한이 꺼진 사용자는 프로필 설정 메뉴에서 상태를 확인할 수 있다
