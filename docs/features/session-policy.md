## 세션 만료 / 토큰 갱신 정책 (Session Policy)

**최종 수정일**: 2026-08-15
**상태**: 🟢 정책 확정
**담당**: 기획/디자인 - OOO / 개발 - OOO
**연관 문서**: `auth-onboarding.md`

### 1. 개요

로그인 토큰의 유효 기간, 자동 갱신 방식, 강제 재로그인 조건을 정의한다.
`auth-onboarding.md`에서 미확정으로 남겨뒀던 항목.

### 2. 정책 (제안 기본값으로 확정)

| 항목 | 값 |
|---|---|
| Access Token 유효기간 | 1시간 |
| Refresh Token 유효기간 | 30일 (슬라이딩 방식 — 아래 참조) |
| 저장 위치 | 기기 보안 저장소 (Keychain/Keystore), `auth-onboarding.md`와 동일 |
| 갱신 방식 | 자동 실행 (Silent Refresh) — 사용자 개입 없음 |
| 멀티 디바이스 | 허용 — 여러 기기에서 동시 로그인 가능, 세션 개별 관리 |

**슬라이딩 방식 (활성 사용자는 로그아웃되지 않음)**
- Access Token이 만료되면 Refresh Token으로 자동 갱신, 이때 Refresh Token도
  함께 갱신되어 유효기간이 30일로 다시 연장됨
- 즉, 30일 이내에 최소 한 번이라도 앱을 켜는 사용자는 재로그인 요구 없이
  계속 이용 가능
- 30일 이상 앱을 켜지 않은 사용자만 Refresh Token이 만료되어 재로그인 필요

### 3. 사용자 시나리오

- 정상 사용 중: 토큰 만료를 사용자가 인지하지 못함 (백그라운드에서 자동 갱신)
- 30일 이상 미접속 후 앱 실행: 스플래시 → 세션 체크 → Refresh Token도
  만료됨 확인 → 로그인 화면으로 이동 (`auth-onboarding.md`의 "세션 없음"
  케이스와 동일 플로우)
- Refresh Token 자체가 탈취/무효화된 경우(보안 이슈 대응): 즉시 로그아웃
  처리 → 로그인 화면

### 4. 데이터 요구사항 (개발자 확인 필요 영역)

- 서버에서 Access/Refresh Token 발급 및 갱신 엔드포인트 필요 (표준 OAuth
  스타일)
- 멀티 디바이스 지원 시, 특정 기기만 로그아웃시키는 기능(예: 회원탈퇴 시
  전체 세션 무효화)은 회원탈퇴 플로우(`profile-settings.md`)와 연동 필요
- **[미확정]** 로그아웃 시 해당 기기 세션만 무효화할지, 전체 기기 세션을
  다 무효화할지 — 기본 가정: 로그아웃은 해당 기기만, 회원탈퇴는 전체 무효화

### 5. 엣지 케이스

- Access Token 갱신 중 네트워크 오류 → `offline-handling.md`의 전역
  오프라인 정책을 따름, 재연결 시 자동 재시도
- 여러 기기에서 동시에 갱신 요청이 몰리는 경우(레이스 컨디션) → 서버
  구현 이슈, **[미확정]** 개발자와 협의

### 6. 완료 조건 (Acceptance Criteria)

- [ ] Access Token은 1시간마다 자동으로 갱신되며 사용자는 이를 인지하지 못한다
- [ ] 30일 이내 재접속 시 재로그인 없이 계속 이용 가능하다
- [ ] 30일 이상 미접속 후에는 재로그인이 요구된다
- [ ] 여러 기기에서 동시 로그인이 가능하다
