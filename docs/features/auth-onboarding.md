## 인증 / 온보딩 (Auth & Splash)

**최종 수정일**: 2026-08-15
**상태**: 🟢 전체 확정
**담당**: 기획/디자인 - OOO / 개발 - OOO

### 1. 개요

앱은 로그인 없이는 사용할 수 없다(게스트 모드 없음). 자체 회원가입 없이
카카오·네이버·구글 3개 소셜 로그인만 제공한다. 최초 실행 시 온보딩 화면은
없고, 스플래시 화면만 거친다.

### 2. 사용자 시나리오

- 앱 실행 → 스플래시 화면 노출(브랜드 이미지 + 로딩) → 세션 체크
  (`session-policy.md` 참조)
  - 유효한 세션 있음 → 홈 탭으로 바로 이동
  - 세션 없음/만료 → 로그인 화면으로 이동
- 로그인 화면에서 카카오/네이버/구글 중 하나를 선택해 로그인
- 로그인 성공 → **위치 권한 시스템 다이얼로그 자동 노출** (`global-states.md` 참조) → 홈 탭으로 이동
- 로그인 실패/취소 → 로그인 화면에 머무름 (에러 메시지 노출)
- 로그인 화면은 뒤로가기·스와이프·닫기 등 어떤 방법으로도 건너뛸 수 없음

### 3. 화면 구성

**스플래시**
- 전체 화면, 중앙 정렬 브랜드 이미지/로고
- ⚠️ 이미지 에셋은 추후 작업 예정 — 지금은 이미지가 들어갈 자리(컨테이너)만
  고정 비율로 잡아두고, 임시 플레이스홀더(로고 텍스트 or 단색 배경)로 대체
- 최소 노출 시간 규칙 필요 — **[미확정]** 세션 체크가 너무 빨리 끝나도
  스플래시가 순간적으로 깜빡이지 않도록 최소 노출 시간(예: 800ms~1.2s)을
  둘지 여부 논의 필요

**로그인 화면**
- 앱 로고/서비스명
- 소셜 로그인 버튼 3개, 세로 배열: 카카오 / 네이버 / 구글
  (버튼 순서·색상은 각 플랫폼 브랜드 가이드라인 준수 필요)
- 뒤로가기 아이콘/스와이프 제스처 비활성화 — 이 화면에서 나가는 유일한
  경로는 "로그인 성공"뿐

### 4. 컴포넌트 & 상태 정의

| 상태 | 조건 | UI 처리 |
|---|---|---|
| 세션 체크 중 | 앱 실행 직후 | 스플래시 유지 |
| 로그인 필요 | 세션 없음/만료 | 로그인 화면, 버튼 3개 모두 활성 |
| 로그인 진행 중 | 소셜 버튼 탭 후 OAuth 진행 | 탭한 버튼만 로딩 스피너, 나머지 버튼 비활성 |
| 로그인 실패 | OAuth 실패/사용자 취소 | 화면 유지 + 하단 에러 토스트 ("로그인에 실패했어요. 다시 시도해주세요") |
| 로그인 성공 | 토큰 발급 완료 | 위치 권한 다이얼로그 노출 → 홈 탭으로 전환 |

### 5. 인터랙션 / 마이크로카피

- 로그인 실패 토스트: "로그인에 실패했어요. 다시 시도해주세요"
- 네트워크 오류 시: "네트워크 연결을 확인해주세요" (일반 에러와 구분)
- 안드로이드 하드웨어 뒤로가기 버튼 처리: 로그인 화면에서는 앱 종료
  확인 다이얼로그만 허용(이전 화면으로 되돌아가는 동작은 없음) —
  **[미확정] 정책 확인 필요**

### 6. 데이터 요구사항 (개발자 확인 필요 영역)

**User 타입 확장 필요**:

```typescript
type AuthProvider = "kakao" | "naver" | "google";

type User = {
  id: string;
  name: string;
  avatar: string;
  streak: number;
  provider: AuthProvider;
  createdAt: string;
  deletedAt: string | null;      // profile-settings.md
  connectedDevices: {             // profile-settings.md
    appleWatch: boolean;
    galaxyWatch: boolean;
  };
};
```

- 최초 로그인 시 닉네임 처리: 소셜 프로필 이름을 기본값으로 사용, 이후
  프로필에서 자유롭게 변경 가능 (`profile-settings.md`에서 확정)
- **세션/토큰 정책은 `session-policy.md`에서 전체 확정** — Access Token
  1시간, Refresh Token 30일 슬라이딩 갱신
- 각 소셜 로그인 앱 키/시크릿 발급 필요 (카카오 디벨로퍼스, 네이버 개발자센터,
  Google Cloud Console) — 기획/개발 중 누가 발급 담당할지 정하기
- 위치 권한 요청 타이밍/재요청 플로우는 `global-states.md`에서 전역 정책으로 정의됨

### 7. 엣지 케이스

- 동일 사용자가 다른 소셜 계정으로 재로그인 시 별도 계정으로 취급할지,
  이메일 기준으로 병합할지 → **[미확정] 정책 결정 필요**
- 로그인 진행 중 앱이 백그라운드로 전환된 경우 처리
- 소셜 플랫폼 자체 장애 시 대응 문구
- 재로그인 사용자에게도 매번 위치 권한 다이얼로그를 다시 띄울지 여부 →
  **[미확정]**
