### 0. 구조 요약

**전체 도시 순서는 고정**된 하나의 마스터 경로다. 각 도시는 기준점
(서울시청)으로부터의 실제 거리값(haversine 대권거리)을 가지며, 이 거리값
오름차순이 곧 고정된 여행 순서가 된다. 사용자는 가입 시점 위치에 따라
이 고정 경로 위 시작 후보 도시 중 하나에 배정되어, 그 지점부터 동일한
순서로 이어지는 도시들을 향해 나아간다.

### 4. 도시별 배경 이미지 (신규 확정)

**진행률 카드의 배경 이미지는 "다음 목적지(아직 도달하지 않은 다음 도시)"
기준으로 표시되며, 도시를 완료할 때마다 자동으로 다음 도시 이미지로
전환된다.**

- 예: 서울에서 출발해 다음 목표가 도쿄인 구간 → 도쿄를 상징하는 이미지
  (예: 도쿄타워) 노출
- 도쿄 도달 완료 → 다음 목표가 베이징으로 전환 → 배경 이미지도 베이징을
  상징하는 이미지(예: 만리장성, 자금성 등)로 자동 교체
- 각 마스터 도시는 **랜드마크 이미지 1장씩**을 매핑해 보유
- **[미확정]** 이미지는 실사진(랜드마크 사진)으로 갈지, 일러스트/아이콘
  스타일로 통일할지 — 앞서 정의한 카드 디자인 톤(다크 배경 + 그라디언트
  오버레이, `RUNNA_KR_기능정의서.md` 7-5 참조)에 맞춰 통일감 있게 선정
  필요
- 이미지 자체(실사진/일러스트 에셋)는 **콘텐츠팀에서 별도 소싱/제작
  필요** — 저작권이 있는 사진을 함부로 쓸 수 없으므로, 라이선스가 확인된
  스톡 이미지 구매 또는 자체 제작 일러스트 권장

> **구현 (2026-09-26) — 전환 로직은 완성, 이미지는 여전히 임시다.**
>
> `JourneyCity.imageKey` 에 22개 도시 이미지를 넣고, 홈 카드가
> `journey.toCity.imageKey`(= 다음 목적지)를 쓰도록 바꿨다. 도시를 지나면
> `toCity` 가 바뀌므로 배경도 따라 바뀐다.
>
> **이미지는 Unsplash 스톡이고 여전히 개발용 임시다.** Unsplash License 가
> 상업적 사용을 허용해 당장 쓰는 데 문제는 없지만, 위 "콘텐츠팀 소싱" 방침을
> 대체하지 않는다. 남은 문제 둘:
> - **핫링크 의존** — `images.unsplash.com` 에서 매번 받는다. 오프라인이면
>   배경이 안 뜨고(조용한 폴백으로 넘어감), 원본이 내려가면 깨진다. 실서비스는
>   앱 번들이나 Supabase Storage 로 옮겨야 한다
> - 실사진/일러스트 방침([미확정])이 정해지면 22개가 통째로 갈린다
>
> **고르는 방법 (다음에 다시 할 때)**: 사진 ID 를 추측하면 안 된다. Unsplash
> 검색 결과의 `img.alt` 에 사진 설명이 들어 있어 **그 사진이 실제로 무엇인지
> 확인할 수 있다.** 도시명으로만 검색하면 무관한 사진이 자주 섞인다 —
> `incheon` 에서 미국 베닝턴 기념비가, `gwangan bridge busan` 에서 금문교가
> 1순위로 나왔다. **랜드마크 고유명**으로 검색해야 정확해진다.
>
> 22개 전부 `https://images.unsplash.com/<id>?w=&h=&fit=crop&auto=format` 로
> 200 응답을 확인했다. **200 은 "그 사진이 있다"지 "그 도시다"가 아니라서**,
> 설명만으로 애매했던 8곳은 이미지를 직접 열어 눈으로 봤다. 코드 주석의
> 등급이 그 결과다 — `[확실]`(설명에 이름이 있음) · `[확인]`(눈으로 봄) ·
> `[추정]`(아직 못 봄, 앙카라 1곳).
>
> 눈으로 보고 **둘을 갈아치웠다**:
> - 인천 — 어느 도시인지 알 수 없는 야경 → **송도 센트럴파크**(수변 + 고층)
> - 프리토리아 — 하늘만 크고 너무 밝음 → **구시가·자카란다**
>
> 🔧 **테스트용 — 여정 카드를 좌우로 넘기면 다른 도시 이미지를 미리 본다.**
> 22개를 다 보려면 19,432km 를 달려야 해서 확인할 방법이 없었다. 짧게 밀면
> 한 칸, 길게 끌면 여러 칸 넘어간다. 미리보기 중에는 라벨이 오렌지
> `미리보기 (테스트)` + 도시명으로 바뀌고 `n / 22` 와 '실제로 돌아가기'가
> 뜬다. 진행률·거리 등 **실제 데이터는 건드리지 않는다.**
>
> **`kDebugMode` 에서만 동작한다.** 실서비스에서 카드를 넘길 수 있으면 아직
> 도달하지 않은 도시를 미리 보게 돼 "달린 만큼 나아간다"는 전제가 깨진다.

> 🔴 **고를 때 구도를 봐야 한다.** 어두운 카드 위에 흰 글씨가 얹히므로
> **하늘이 대부분인 사진은 배경으로 못 쓴다.** 랜드마크가 맞아도 프레임을
> 못 채우면 카드가 단색처럼 보인다(브라질리아 대성당이 그 경계선이라
> 주석에 남겼다).

### 6. 데이터 요구사항 (개발자 확인 필요 영역)

```typescript
type MasterCity = {
  id: string;
  name: string;
  countryName: string | null;
  lat: number;
  lng: number;
  cumulativeKm: number;
  isStartCandidate: boolean;
  backgroundImageUrl: string;   // 신규 — 도시별 랜드마크 이미지
};

type JourneyState = {
  assignedStartCityId: string;
  startResolvedFromGPS: boolean;
  startedAt: string;
  totalDistanceKm: number;
  currentMilestoneIndex: number;
};
```

- 사용자의 절대 위치 = `assignedStartCity.cumulativeKm + totalDistanceKm`
- 시작 도시보다 앞선 도시는 배지 지급 대상에서 제외
- 진행률 카드 배경 이미지 렌더링 로직: `masterCities[currentMilestoneIndex + 1].backgroundImageUrl` (다음 목적지 기준)
- 모든 마스터 도시에 이미지가 매핑돼 있어야 전 구간에서 배경이 비지 않음 — **[미확정]** 이미지가 아직 준비 안 된 도시는 어떤 기본 이미지로 대체할지(플레이스홀더)
