## 공통 / 전역 상태 (Error / Loading / Location Permission)

**최종 수정일**: 2026-08-15
**상태**: 🟢 핵심 정책 확정 · 세부 카피/타이밍 일부 미확정
**담당**: 기획/디자인 - OOO / 개발 - OOO
**성격**: 특정 화면이 아니라 앱 전역에 적용되는 공통 패턴. 한 번 정의하면
모든 화면(홈/달리기/기록/콘텐츠/프로필)에 동일하게 적용한다.

### 1. 개요

에러 처리, 로딩 처리, 위치 권한 요청은 화면마다 따로 정의하지 않고
전역 공통 컴포넌트/정책으로 통일한다.

### 2. 사용자 시나리오

**에러 발생 시**
- API 호출 실패 → 해당 영역에 인라인 에러 상태 노출, "다시 시도" 버튼 탭 시
  동일 요청을 재호출

**로딩 시**
- 데이터를 불러오는 동안 콘텐츠 자리에 스켈레톤(회색 뼈대) 노출, 로딩 완료 시
  실제 콘텐츠로 교체

**위치 권한**
- 로그인 성공 직후, 홈 탭 진입과 함께 시스템 위치 권한 다이얼로그가 자동으로 뜬다
- 허용 → 정상 진행, 이후 별도 요청 없음
- 거부 → 앱 사용은 그대로 허용(달리기 탭 진입도 가능), 단 실제로 달리기를
  시작하려는 시점(START 버튼)에 다시 안내

### 3. 화면 구성

**에러 상태 (인라인, 다시 시도 버튼 기반)**

| 요소 | 내용 |
|---|---|
| 아이콘/일러스트 | 중립적인 경고 아이콘 |
| 문구 | "불러오지 못했어요" |
| 버튼 | "다시 시도" — 탭 시 직전에 실패한 요청을 동일하게 재호출 |

> 목록/화면 단위 로딩 실패에 적용. 버튼 탭이나 참가하기 같은 "액션성" 요청이
> 실패했을 때도 동일하게 인라인보다는 액션 지점 근처에 재시도 버튼을 붙이는
> 방식으로 통일 — 화면 전체를 인라인 에러로 덮지 않고, 실패한 부분만 표시

**로딩 상태 (스켈레톤)**

- 카드/리스트 아이템 모양 그대로 회색 뼈대로 표시, 실제 데이터 도착 시 페이드 전환
- 적용 대상: 홈 스트릭, 기록 리스트, 콘텐츠 카드 목록, 프로필 통계 등 데이터 의존 영역 전체

**위치 권한 — 3단계 플로우**

| 단계 | 시점 | 화면 처리 |
|---|---|---|
| 1차 요청 | 로그인 성공 직후, 홈 탭 진입 시 | OS 시스템 권한 다이얼로그 자동 노출 |
| 2차 안내 | 1차에서 거부 + 이후 "달리기" 탭에서 START 탭 시 | **앱 자체 안내 모달** — "러닝 기록을 위해 위치 권한이 필요해요" + "설정으로 이동" 버튼 (OS가 재요청을 허용하는 경우 시스템 다이얼로그도 함께 시도) |
| 최종 차단 안내 | 2차 안내 이후에도 권한 미허용 상태로 START를 다시 시도 | 블로킹 팝업 — "위치 권한이 없으면 러닝을 시작할 수 없어요" + "확인" 버튼(팝업만 닫힘, 권한 상태는 변화 없음) |

> ⚠️ **플랫폼 제약**: iOS/최신 Android는 사용자가 시스템 다이얼로그에서 한 번
> 거부하면, 앱이 재요청해도 **시스템 다이얼로그가 다시 뜨지 않고 즉시 "거부"
> 응답만 돌아옵니다.** 따라서 2단계부터는 실질적으로 "시스템 다이얼로그
> 재노출"이 아니라 **앱 자체 안내 모달(설정 앱으로 딥링크)**이 그 역할을
> 대신합니다. START를 반복해서 눌러도 매번 이 2차 안내 모달 → (거부 유지 시)
> 최종 차단 팝업이 반복되는 구조입니다.

### 4. 컴포넌트 & 상태 정의

| 상태 | 조건 | UI 처리 |
|---|---|---|
| `locationPermission: "granted"` | 권한 허용됨 | START 정상 동작 |
| `locationPermission: "denied"`, 최초 진입 | 1차 거부 후 아직 START 미시도 | 달리기 탭 정상 진입 가능, 특별한 배너 없음 |
| `locationPermission: "denied"`, START 최초 시도 | 2차 안내 단계 | 앱 자체 모달 노출 (설정 이동 유도) |
| `locationPermission: "denied"`, 2차 안내 이후 재시도 | 최종 차단 단계 | 블로킹 팝업, 확인 시 팝업만 닫힘 (달리기 시작 안 됨) |

### 5. 인터랙션 / 마이크로카피

- 1차 시스템 다이얼로그: OS 기본 문구 사용 (커스터마이징 불가 영역)
- 2차 안내 모달: "러닝 기록을 위해 위치 권한이 필요해요" + "설정으로 이동" / "취소"
- 최종 차단 팝업: "위치 권한이 없으면 러닝을 시작할 수 없어요" + "확인"
- 에러 인라인: "불러오지 못했어요" + "다시 시도"

### 6. 데이터 요구사항 (개발자 확인 필요 영역)

```typescript
type LocationPermissionState = "granted" | "denied" | "not_determined";
```

- 권한 상태는 앱 재실행/포그라운드 복귀 시마다 최신값으로 재조회 필요
  (사용자가 기기 설정에서 직접 켰다 껐다 할 수 있으므로)
- "2차 안내"와 "최종 차단"을 구분하는 카운터 또는 플래그 필요 — 세션 내에서만
  유지할지, 영구 저장할지는 **[미확정]** (예: 앱을 껐다 켜면 다시 2차부터
  시작할지, 최종 차단 상태를 기억할지)
- 에러 "다시 시도" 버튼은 직전 실패 요청의 파라미터를 그대로 재사용해야 함
  (요청 컨텍스트 저장 필요)

### 7. 엣지 케이스

- 사용자가 2차 안내 모달에서 "설정으로 이동" 후 실제로 권한을 켜고 앱으로
  복귀한 경우 → 복귀 시점에 권한 상태 재확인해서 정상 진행되도록 처리
- 로그인 성공 직후 1차 요청 시점에 이미 과거에 권한을 거부한 이력이 있는
  사용자(재로그인 케이스) → 매번 로그인마다 시스템 다이얼로그를 다시 띄울지,
  최초 1회만 띄울지 **[미확정]**
- 네트워크 에러와 서버 에러(4xx/5xx)를 같은 에러 UI로 통일할지, 문구를
  다르게 할지 **[미확정]**

### 8. 완료 조건 (Acceptance Criteria)

- [ ] 모든 데이터 의존 화면에서 로딩 시 스켈레톤이 노출된다
- [ ] API 실패 시 인라인 에러 + "다시 시도" 버튼이 노출되고, 탭 시 동일 요청이 재호출된다
- [ ] 로그인 성공 직후 홈 탭 진입과 함께 위치 권한 시스템 다이얼로그가 노출된다
- [ ] 권한 거부 상태로 달리기 탭에 진입해도 화면 자체는 정상적으로 보인다
- [ ] START 최초 시도 시 앱 자체 안내 모달(설정 이동 유도)이 노출된다
- [ ] 안내 모달 이후에도 거부 상태로 START 시도 시 블로킹 팝업이 노출되고, 확인 시 팝업만 닫힌다
- [ ] 팝업을 닫고 다시 START를 누르면 2차 안내부터 반복된다
