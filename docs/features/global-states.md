## 공통 / 전역 상태 (Error / Loading / Location Permission)

**최종 수정일**: 2026-08-15
**상태**: 🟢 전체 확정 · 구현 완료 (2026-09-26 — [미확정] 3건 모두 정리)
**담당**: 기획/디자인 - OOO / 개발 - OOO
**성격**: 특정 화면이 아니라 앱 전역에 적용되는 공통 패턴. 한 번 정의하면
모든 화면(홈/달리기/기록/콘텐츠/프로필)에 동일하게 적용한다.

### 1. 개요

에러 처리, 로딩 처리, 위치 권한 요청은 화면마다 따로 정의하지 않고
전역 공통 컴포넌트/정책으로 통일한다.

### 2. 사용자 시나리오

**에러 발생 시**
- API 호출 실패 → 해당 영역에 인라인 에러 상태 노출, "다시 시도" 버튼 탭 시
  동일 요청을 재호출

**로딩 시**
- 데이터를 불러오는 동안 콘텐츠 자리에 스켈레톤(회색 뼈대) 노출, 로딩 완료 시
  실제 콘텐츠로 교체

**위치 권한**
- 로그인 성공 직후, 홈 탭 진입과 함께 시스템 위치 권한 다이얼로그가 자동으로 뜬다
- 허용 → 정상 진행, 이후 별도 요청 없음
- 거부 → 앱 사용은 그대로 허용(달리기 탭 진입도 가능), 단 실제로 달리기를
  시작하려는 시점(START 버튼)에 다시 안내

### 3. 화면 구성

**에러 상태 (인라인, 다시 시도 버튼 기반)**

| 요소 | 내용 |
|---|---|
| 아이콘/일러스트 | 중립적인 경고 아이콘 |
| 문구 | "불러오지 못했어요" |
| 버튼 | "다시 시도" — 탭 시 직전에 실패한 요청을 동일하게 재호출 |

> 목록/화면 단위 로딩 실패에 적용. 버튼 탭이나 참가하기 같은 "액션성" 요청이
> 실패했을 때도 동일하게 인라인보다는 액션 지점 근처에 재시도 버튼을 붙이는
> 방식으로 통일 — 화면 전체를 인라인 에러로 덮지 않고, 실패한 부분만 표시

> **구현 (2026-09-26)** — `core/widgets/inline_error.dart` 의 `InlineError`.
>
> - Scaffold 를 만들지 않고 **자기 자리만 채운다**(위 "화면 전체를 덮지 않고").
>   좁은 자리용 `compact: true` 가 따로 있다.
> - **`onRetry` 가 null 이면 버튼을 그리지 않는다.** 재호출할 요청이 없는데
>   버튼만 두면 눌러도 아무 일도 안 하는 버튼이 된다. 지금 그런 곳:
>   출발 전 화면의 미세먼지(에어코리아 키 대기), 기록 상세의 "기록을 찾을
>   수 없어요"(다시 읽어도 없는 id 는 없다).
> - 기록 탭·기록 상세의 재시도는 `ref.invalidate(runsStreamProvider)` —
>   다시 구독하면 drift 가 처음부터 흘려준다.

> 🟡 **아직 없는 것 — 로컬 DB 읽기가 영영 안 끝나는 경우.** 지금 구조는
> 뼈대를 세워두고 값이 오기만 기다린다. 타임아웃이 없어서, 스트림이 값도
> 에러도 주지 않으면 **뼈대에 영원히 머문다.** 실제로 위젯 테스트 환경이
> 그 상태다(2026-09-26 에 발견). 기기에서는 drift 가 빈 테이블이어도 빈
> 목록을 즉시 주므로 재현되지 않지만, 구조적으로 빠져 있는 건 맞다.

**로딩 상태 (스켈레톤)**

- 카드/리스트 아이템 모양 그대로 회색 뼈대로 표시, 실제 데이터 도착 시 페이드 전환
- 적용 대상: 홈 스트릭, 기록 리스트, 콘텐츠 카드 목록, 프로필 통계 등 데이터 의존 영역 전체

> **구현 (2026-09-26)** — `core/widgets/skeleton.dart` 의 `SkeletonBox`·`SkeletonCard`.
>
> - **뼈대는 실물과 같은 치수로 세운다.** 위젯이 크기를 스스로 정하지 않고
>   쓰는 쪽이 준다 — 뼈대가 실물과 다르면 데이터가 도착할 때 화면이 튄다.
> - 색은 `muted`(#151923). `card`(#0D1018)와 배경 사이라 "자리는 있는데
>   아직 비었다"로 읽힌다.
> - 효과는 shimmer 가 아니라 **불투명도 펄스(1.1초)**. 패키지가 필요 없고,
>   배경이 거의 검정이라 빛줄기가 과하게 도드라진다.
> - **적용된 곳**: 기록 탭 목록 · 기록 상세 · 홈(여정·통계·스트릭) ·
>   프로필 통계. **콘텐츠 탭은 아직 아니다** — 목록이 앱에 내장된 샘플이라
>   로딩 구간이 없다(`offline-handling.md` 2 케이스 C 구현 노트와 같은 사정).
> - 홈의 START 버튼은 뼈대로 덮지 않는다. 기록을 읽는 것과 무관하게 언제나
>   눌려야 한다(오프라인에서도 러닝은 된다).
>
> 🔴 **주의 — 펄스는 끝나지 않는 애니메이션이라 `pumpAndSettle` 이 타임아웃한다.**
> 뼈대가 보이는 화면을 위젯 테스트로 다룰 때는 `pump(Duration)` 으로 직접
> 프레임을 돌려야 한다(`test/widget_test.dart` 참조).

**위치 권한 — 3단계 플로우**

| 단계 | 시점 | 화면 처리 |
|---|---|---|
| 1차 요청 | 로그인 성공 직후, 홈 탭 진입 시 | OS 시스템 권한 다이얼로그 자동 노출 |
| 2차 안내 | 1차에서 거부 + 이후 "달리기" 탭에서 START 탭 시 | **앱 자체 안내 모달** — "러닝 기록을 위해 위치 권한이 필요해요" + "설정으로 이동" 버튼 (OS가 재요청을 허용하는 경우 시스템 다이얼로그도 함께 시도) |
| 최종 차단 안내 | 2차 안내 이후에도 권한 미허용 상태로 START를 다시 시도 | 블로킹 팝업 — "위치 권한이 없으면 러닝을 시작할 수 없어요" + "확인" 버튼(팝업만 닫힘, 권한 상태는 변화 없음) |

> **구현 (2026-09-26)** — `run_screen._ensureLocationPermission()`.
>
> - **위치 권한을 알림·절전보다 먼저 묻는다.** 거부면 러닝이 아예 시작되지
>   않는데 알림부터 묻는 건 순서가 거꾸로다 — 다 허락해놓고 마지막에
>   "시작할 수 없어요"를 보게 된다.
> - **2차 안내에서 시스템 다이얼로그를 다시 부르지 않는다.** 아래 플랫폼
>   제약대로 즉시 거부가 돌아와, 사용자에겐 아무 일도 안 일어난 것처럼
>   보인다. 앱 모달 + `openAppSettings()` 만 쓴다.
> - 기기 GPS 자체가 꺼진 경우는 권한 흐름에 섞지 않고 따로 알린다(앱이
>   손쓸 수 없는 일이라 모달 3단계와 성격이 다르다).
> - `RunTracker` 에 `locationPermission()`·`requestLocationPermission()` 을
>   두어 화면이 `geolocator` 의 5가지 대신 문서가 정한 3가지
>   (`LocationPermissionState`)만 보게 했다. 알림 권한과 같은 모양이다.
> - `RunTracker._ensurePermission()` 은 **안전망으로 남겨뒀다** — 복원
>   (`restoreIfAny`)처럼 화면을 거치지 않고 스트림을 여는 경로가 있다.

> ⚠️ **플랫폼 제약**: iOS/최신 Android는 사용자가 시스템 다이얼로그에서 한 번
> 거부하면, 앱이 재요청해도 **시스템 다이얼로그가 다시 뜨지 않고 즉시 "거부"
> 응답만 돌아옵니다.** 따라서 2단계부터는 실질적으로 "시스템 다이얼로그
> 재노출"이 아니라 **앱 자체 안내 모달(설정 앱으로 딥링크)**이 그 역할을
> 대신합니다. START를 반복해서 눌러도 매번 이 2차 안내 모달 → (거부 유지 시)
> 최종 차단 팝업이 반복되는 구조입니다.

### 4. 컴포넌트 & 상태 정의

| 상태 | 조건 | UI 처리 |
|---|---|---|
| `locationPermission: "granted"` | 권한 허용됨 | START 정상 동작 |
| `locationPermission: "denied"`, 최초 진입 | 1차 거부 후 아직 START 미시도 | 달리기 탭 정상 진입 가능, 특별한 배너 없음 |
| `locationPermission: "denied"`, START 최초 시도 | 2차 안내 단계 | 앱 자체 모달 노출 (설정 이동 유도) |
| `locationPermission: "denied"`, 2차 안내 이후 재시도 | 최종 차단 단계 | 블로킹 팝업, 확인 시 팝업만 닫힘 (달리기 시작 안 됨) |

### 5. 인터랙션 / 마이크로카피

- 1차 시스템 다이얼로그: OS 기본 문구 사용 (커스터마이징 불가 영역)
- 2차 안내 모달: "러닝 기록을 위해 위치 권한이 필요해요" + "설정으로 이동" / "취소"
- 최종 차단 팝업: "위치 권한이 없으면 러닝을 시작할 수 없어요" + "확인"
- 에러 인라인: "불러오지 못했어요" + "다시 시도"
