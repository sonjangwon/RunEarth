## 웨어러블 데이터 동기화 (Wearable Sync)

**최종 수정일**: 2026-08-15
**상태**: 🟢 스코프/로직 확정
**담당**: 기획/디자인 - OOO / 개발 - OOO
**연관 문서**: `profile-settings.md`(연결 화면), `run-flow.md`(Run 데이터 모델), `journey.md`/`streak.md`/`badges.md`(누적 반영 대상)

### 1. 개요 및 스코프 결정

**워치 전용 네이티브 앱(watchOS/Wear OS)을 별도 개발하는 방식이 아니라,
Apple Health / 삼성 Health(Health Connect) 같은 기존 헬스 플랫폼을 통해
이미 기록된 워크아웃 데이터를 앱으로 가져오는(import) 방식**으로 스코프를
확정한다.

- 사용자가 애플워치의 운동 앱(또는 갤럭시워치의 삼성 헬스)으로 직접
  러닝을 기록하면, 그 데이터가 Apple Health / 삼성 Health에 저장됨
- Run Earth 앱이 이 헬스 플랫폼에서 러닝 관련 워크아웃을 읽어와 자동으로
  기록으로 가져옴 (**단방향: 워치/헬스 앱 → Run Earth**, 역방향 쓰기는
  범위 밖)
- 실시간으로 워치 화면에 앱을 미러링하거나, 워치에서 START/STOP을
  조작하는 기능은 **이번 스코프에서 제외** (별도 네이티브 워치 앱 개발이
  필요한 훨씬 큰 작업)

### 2. 사용자 시나리오

- 프로필 > 기기 연동에서 "애플워치" 또는 "갤럭시워치" 연결 탭
  (`profile-settings.md`) → OS 헬스 데이터 읽기 권한 요청
- 권한 허용 후, 사용자가 워치로 러닝을 기록하면:
  - 앱이 주기적으로(또는 앱 실행 시) 헬스 플랫폼에서 새 러닝 워크아웃을
    확인
  - 새 워크아웃 발견 → 자동으로 "기록" 탭에 새 항목으로 추가
- 사용자가 폰을 들고 뛰면서 동시에 워치도 착용한 경우(둘 다 기록 시도) →
  같은 시간대 기록으로 판단되면 **중복 저장 방지** (아래 4번 참조)

### 3. 데이터 매핑

| 워치/헬스 데이터 | Run Earth 매핑 |
|---|---|
| 거리, 시간, 칼로리 | `Run.km`, `Run.dur`, `Run.kcal` |
| GPS 경로(있는 경우) | `coverImageType: "route"`로 자동 렌더 (`run-flow.md`와 동일 로직) |
| 워크아웃 종류 | 러닝 종류로 필터링(걷기/자전거 등은 가져오지 않음) |
| 러닝 타입(`RecordType`) | **항상 "일반"으로 고정 저장** — 테마/온라인 마라톤 참여 여부는 앱 자체 플로우로만 판별 가능하므로, 워치에서 가져온 기록은 테마/온라인으로 분류할 수 없음 |

### 4. 중복 방지 로직

- 같은 사용자의 기존 기록(폰 GPS로 직접 기록한 것) 중 **시간대가 겹치는
  워크아웃**이 있으면, 워치 데이터는 새로 추가하지 않고 무시
- **[미확정]** "겹침" 판단 기준(예: 시작 시각이 ±10분 이내인지)은 정확한
  임계값 협의 필요

### 5. 컴포넌트 & 상태 정의

| 상태 | 조건 | 처리 |
|---|---|---|
| 미연동 | 헬스 권한 없음 | 동기화 없음, 기존 폰 GPS 트래킹만 정상 동작 |
| 연동됨 | 헬스 권한 허용 | 주기적으로 새 워크아웃 확인 및 자동 가져오기 |
| 동기화 실패 | 헬스 API 오류 | 조용히 다음 주기에 재시도 (사용자에게 에러 노출 안 함 — 부가 기능이므로) |

### 6. 데이터 요구사항 (개발자 확인 필요 영역)

```typescript
type Run = {
  // ...기존 필드
  source: "app" | "apple_health" | "samsung_health"; // 신규 — 기록 출처
};
```

- iOS: HealthKit 연동, `HKWorkoutType`(러닝) 읽기 권한 필요
- Android: Health Connect(또는 삼성 Health SDK) 연동
- 동기화 주기: **[미확정]** 앱 실행 시마다 확인 vs 백그라운드 주기적
  확인(배터리 영향 고려 필요) — 제안 기본값: 앱 포그라운드 진입 시마다 확인
- 여정(`journey.md`)/스트릭(`streak.md`)/배지(`badges.md`)는 `Run.km`
  전체 합산 기준이므로, 워치에서 가져온 기록도 **자동으로 동일하게 반영됨**
  (별도 로직 불필요, 기존 집계 방식 그대로 적용)

### 7. 엣지 케이스

- 사용자가 워치 연동을 나중에 해제하면, 이미 가져온 과거 기록은 그대로
  유지할지 삭제할지 → **[미확정]**, 기본 가정: 유지 (기록은 영구 보존
  원칙이 이미 있으므로)
- 워치에서 매우 짧은 거리(예: 100m)의 "실수 기록"도 그대로 가져올지 →
  **[미확정]** 최소 거리 필터 여부

### 8. 완료 조건 (Acceptance Criteria)

- [ ] 기기 연동에서 권한 허용 시 헬스 플랫폼의 러닝 워크아웃을 자동으로 가져온다
- [ ] 가져온 기록은 "일반" 타입으로 기록 탭에 정상 노출된다
- [ ] 폰 GPS로 이미 기록한 것과 시간이 겹치는 워치 기록은 중복 저장되지 않는다
- [ ] 워치에서 가져온 기록도 여정/스트릭/배지 집계에 정상 반영된다
