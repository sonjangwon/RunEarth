### 1. 개요

기록 탭의 데이터 관리 정책(삭제/수정 가능 여부)과, 온라인 마라톤 관련 특수
뱃지 표시 규칙(미인정/최고기록)을 정의한다.

### 2. 사용자 시나리오

- 사용자는 과거 기록을 삭제할 수 없다 (영구 보존)
- 기록 상세에서 **대표 이미지만** 수정 가능 (거리/시간/페이스 등 수치는 불가)
- 온라인 마라톤 참여 기록 중 GPS 코스 인정 조건을 충족하지 못한 경우,
  기록 카드에 "미인정" 작은 뱃지가 표시된다
- 동일한 코스(`courseId` 기준)에 여러 번 도전한 기록이 있는 경우, 그중
  **가장 빠른 기록에만** "최고기록" 뱃지가 표시된다 — 서로 다른 회차/기간의
  챌린지라도 물리적으로 같은 코스면 대상에 포함됨
- 기록이 하나도 없는 사용자는 심플한 빈 상태 화면을 본다
- **미완료 러닝(거리 0)은 목록에 아예 나오지 않는다** (2026-09-26 개정).
  DB 에는 그대로 남지만 화면에는 내보내지 않는다. 예전에는 접어두고
  "미완료 러닝 N건 보기" 토글로 펼칠 수 있었다

### 3. 화면 구성

#### 3-1. 목록 정렬 — **최신 순** (2026-09-25 명문화)

원래 이 문서에 정렬 규칙이 없었다. 코드 주석의 "최신순" 한 마디가 유일한
근거였고, 그래서 구현이 어긋난 걸 한참 뒤에야 사용자가 발견했다.

**같은 날 여러 번 뛰었으면 나중에 뛴 것이 위에 온다.**

| 순서 | 키 | 왜 |
|---|---|---|
| 1 | `year` 내림차순 | `date` 가 `"09.23"` 문자열이라 연도를 못 본다. 이것만으로 정렬하면 **해가 바뀔 때 작년 12월이 맨 위로 온다** |
| 2 | `date` 내림차순 | 같은 해 안에서는 `"MM.DD"` 문자열 비교가 곧 날짜 순이다 |
| 3 | `id` 내림차순 | 같은 날의 순서. 앱이 만드는 id 가 `run_<microsecondsSinceEpoch>` 라 시간순이 된다 |

⚠️ **3번은 임시 방편이다.** id 에 시각이 들어 있다는 데 기대고 있어서, 그
규칙을 안 따르는 기록이 들어오면 다시 어긋난다 — **웨어러블 동기화**가 그
경우다. 그때는 `startedAt` 시각 칼럼을 추가해야 하고, `wearable-sync.md` 4 의
"시간대가 겹치는 워크아웃" 판정도 어차피 그 값을 요구한다.

**기록 카드 — 뱃지 추가**

| 뱃지 | 노출 조건 | 스타일 제안 |
|---|---|---|
| 미인정 | `type === "온라인"` && GPS 코스 인정 실패 | 무채색 소형 뱃지 (`--muted` 배경, `--muted-foreground` 텍스트) |
| 최고기록 | `type === "온라인"` && 동일 `courseId` 내 본인 최고 기록 | 강조 뱃지 (골드/옐로우 계열, 온라인 타입 뱃지 색 `#FACC15` 계열과 통일) |
| 동기화 대기 | 로컬에만 있고 아직 서버에 업로드되지 않음 (`runs.synced_at IS NULL`) | 무채색 소형 뱃지 (`--muted` 배경, `--muted-foreground` 텍스트) |

> 두 뱃지는 동시에 노출되지 않음 (미인정 기록은 애초에 랭킹/최고기록 계산
> 대상에서 제외되므로)

> '동기화 대기' 는 위 둘과 성격이 다르다(성취가 아니라 일시적 상태) — 업로드가
> 끝나면 사라지며, 미인정/최고기록과 동시에 노출될 수 있다.
> 출처는 `offline-handling.md` §2 케이스 B.

**빈 상태 (기록 0건)**
- 심플하게 "아직 기록이 없어요" 문구만 노출 (별도 CTA 버튼 없음)

**기록 상세 (수정 가능 범위)**
- 대표 이미지 변경 버튼만 노출 (`run-flow.md` 참조)
- 거리/페이스/시간/칼로리 등 수치 필드는 읽기 전용, 수정 UI 자체를 두지 않음
  - **칼로리는 체중 80kg 을 가정한 추정값이다 (2026-10-03 사용자 결정).**
    체중 입력 수단이 `profile-settings.md` 에 없어 고정값을 쓴다.
    - 식: `80 × 거리(km)` 반올림 (달리기는 속도와 거의 무관하게 1kg·1km 당 약 1kcal)
    - **추정값은 저장하지 않고 화면에서 계산한다.** `Run.kcal` 에 값이 있으면
      (워치 연동 등) 그것을 우선한다. 저장하면 이미 올라간 기록을 다시 올려야
      하고, 내려받기가 로컬 값을 유지해(`offline-handling.md` §4-1) 기기마다 숫자가
      어긋난다. 코드: `run.dart` 의 `kAssumedWeightKg` · `displayKcal`
    - 결과가 0(0km 미완료)이면 **`--`** — `0` 은 "태운 게 없다"는 값으로 읽힌다(2026-09-25)
    - 추정 표시(`≈` 등)는 붙이지 않는다 (2026-10-03 사용자 결정)
    - 체중 입력이 생기면 `kAssumedWeightKg` 자리만 바꾼다. 음소거 설정과 같은
      저장소가 될 것이다(`run-flow.md` 9)
  - **평균 심박수·케이던스는 `--` 로 칸만 둔다.** 워치에서 받는 값이라
    (`wearable-sync.md`, MVP 이후) 지금은 값이 없다. 칸을 지우지 않는 이유는
    연동됐을 때 레이아웃이 흔들리지 않게 하려는 것 (2026-10-03 문서화 — 그전엔
    `run_detail_view.dart` 주석에만 있었다)
  > **구현 노트(2026-09-19)**: 기록 상세 화면 구현 완료. 기능정의서 5 대로

  > ✕ / ← 로 갈린다. 상단에 러닝 타입·'동기화 대기' 뱃지를 함께 붙였다.
  >
  > **대표 이미지 변경 버튼은 아직 두지 않았다.** `run-flow.md` 5 의 바텀시트는

  > 모든 기록이 이미 경로 이미지다 — 전환할 대상이 없어 눌러도 아무 일도

  > 경로는 저장된 PNG 를 읽지 않고 `route` 좌표로 **매번 다시 그린다**

#### 4-1. 0km 기록 정책 (2026-09-26 개정 — 2026-09-23 · 최초 2026-09-20)

> 🟢 **2026-09-26 개정 — 토글을 없애고 완전히 숨긴다 (사용자 결정).**
>
> 2026-09-20 에 토글을 넣은 이유는 "지운 게 아님이 사용자 눈에도 보여야
> 한다" 였다. 그 이유를 접고 **화면에서 완전히 빼기로 했다.** DB 영구 보존
> (§4)은 그대로다 — 저장은 하되 내보내지 않는다.
>
> 🔴 **감수하는 것**: `§7` 의 "1분 이상 뛰었는데 GPS 실패로 0km" 인 경우,
> **실제로 뛴 러닝이 화면에서 통째로 사라진다.** 사용자에게는 앱이 기록을
> 날린 것처럼 보인다. 2026-09-26 노트8 실측에서 절전 모드 때문에 205초가
> 끊긴 사례가 있었으므로 가상의 상황이 아니다.
>
> 이 증상이 실제로 보고되면 **"짧은 것만 숨기고 긴 것은 남기는"**
> 절충(2026-09-20 원안의 시간 조건 복원)을 다시 검토한다.

START 를 눌렀다 만 기록이 스트릭과 총 횟수를 오염시키는 문제를 정리했다.

**판정**: 거리 `< 0.01km`. **시간은 보지 않는다.** 코드 정본은 `Run` 확장의
`isIncomplete`.

**저장은 전부 하고, 세는 것과 보여주는 것만** 조정한다. 위 §4 의 '삭제 불가·
영구 보존'은 데이터를 지키자는 것이지 표시를 강제하는 게 아니므로 충돌하지
않는다.

##### 2026-09-20 의 시간 조건을 왜 뺐나

처음에는 거리 `< 0.01km` **그리고** 시간 `< 60초` 를 **둘 다** 만족할 때만
'미완료'로 봤다. 거리 0 이 성격이 다른 두 가지를 구분하지 못한다는 이유였다:

| 유형 | 예시 | 2026-09-20 | 2026-09-23 |
|---|---|---|---|
| 잘못 눌렀다 만 것 | 22초 · 0.00km (`run_1789742870933776`) | 접는다 | 접는다 |
| 뛰었는데 GPS 를 못 잡은 것 | 1분 37초에 좌표 1개 (`run_1789297203613307`) | **남긴다** | **접는다** |

사용자 결정(2026-09-23)으로 **거리만** 본다. 맞바꾼 것이 분명하다:

- **잃는 것** — GPS 를 못 잡은 날은 실제로 뛰었어도 목록에서 접히고 연속이
  끊긴다. 2026-09-20 이 지키려던 바로 그 경우다.
- **얻는 것** — 보이는 것과 세는 것의 기준이 하나다. 기준이 둘이면 목록에
  카드가 7 개인데 '총 횟수 8회' 같은 어긋남이 생긴다.

되돌리려면 `isIncomplete` 에 `&& durSeconds < 60` 을 다시 넣으면 된다.
`durSeconds` 는 총 시간 합산에도 쓰이므로 그대로 남아 있다.

**적용 범위**: 기록 목록(기본 숨김) · 기록 탭 요약 통계 · 홈 총 횟수/총 거리/
총 시간 · **스트릭**(`streak.md` §2). 스트릭이 가장 중요하다 — 0km 를 세면
연속 기록이 "매일 뛰었다"가 아니라 "매일 버튼을 눌렀다"가 된다.

**요약 통계는 토글과 무관하게 항상 완료 기록만 센다.** 펼쳐 봤다고 총 횟수가
늘면 어느 쪽이 진짜인지 알 수 없다. 펼쳤을 때 카드에는 '미완료' 칩이 붙어
왜 접혀 있었는지 알 수 있다.

### 5. 데이터 요구사항 (개발자 확인 필요 영역)

**`Marathon` 타입 확장 필요** (`online-marathon.md`의 기존 타입에 추가):

```typescript
type Marathon = {
  id: string;         // 신규 — 챌린지(회차) 고유 ID
  courseId: string;   // 신규 — 코스 고유 ID, 여러 회차가 동일 코스를 공유할 수 있음
  name: string;
  distance: string;
  course: string;
  location: string;
  dday: string;
  prize: string;
  prizeEmoji: string;
  joined: boolean;
  ended: boolean;
  participants: string;
  myRank: string | null;
  myTime: string | null;
  img: string;
};
```

**`Run` 타입 확장 필요** (`run-flow.md`의 기존 확장에 추가):

```typescript
type Run = {
  // ...기존 필드 + coverImageType, coverImageUrl (run-flow.md)
  marathonChallengeId?: string;  // 신규 — type이 "온라인"일 때만, 참여한 챌린지(회차) ID
  marathonCourseId?: string;     // 신규 — type이 "온라인"일 때만, 코스 ID (뱃지 계산용)
  gpsVerified?: boolean;         // 신규 — type이 "온라인"일 때만, GPS 코스 인정 여부
};
```

**최고기록 뱃지 계산 로직**
- 특정 사용자의 `type === "온라인"` && `gpsVerified === true`인 기록들을
  `marathonCourseId` 기준으로 그룹핑
- 각 그룹에서 가장 빠른 기록(`dur` 최소값) 1건에만 "최고기록" 뱃지 부여
- **[미확정]** 챌린지가 진행 중이 아닌 시점(예: 이벤트 종료 후 개인적으로
  같은 코스를 또 뛴 경우)의 기록도 이 뱃지 계산에 포함할지 여부 →
  기본적으로는 **포함하는 것으로 가정** (개인 최고기록 개념이므로 공식
  랭킹과는 별개)

### 6. 엣지 케이스

- 동일 `courseId`에 대해 아직 한 번도 코스 인정을 받은 기록이 없는 경우
  (전부 미인정) → 최고기록 뱃지 대상 자체가 없음, 정상
- 최고기록이 동률인 경우(초 단위까지 동일) → **[미확정]** 처리 방식(둘 다
  뱃지 부여 vs 먼저 기록한 쪽 우선) — 발생 확률 낮아 우선순위는 낮음
- ~~기록이 전부 미완료인 경우 → 빈 상태 위에 토글이 남는다~~ → **토글이
  없어졌다(2026-09-26).** 기록이 전부 미완료면 화면은 완전한 빈 상태가 된다
- 1분 이상 뛰었는데 거리가 0 인 경우(GPS 실패) → **미완료다**(2026-09-23 개정).
  DB 에는 그대로 남지만 **화면에서는 보이지 않는다**(2026-09-26 개정)
