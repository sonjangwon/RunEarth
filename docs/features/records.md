### 1. 개요

기록 탭의 데이터 관리 정책(삭제/수정 가능 여부)과, 온라인 마라톤 관련 특수
뱃지 표시 규칙(미인정/최고기록)을 정의한다.

### 2. 사용자 시나리오

- 사용자는 과거 기록을 삭제할 수 없다 (영구 보존)
- 기록 상세에서 **대표 이미지만** 수정 가능 (거리/시간/페이스 등 수치는 불가)
- 온라인 마라톤 참여 기록 중 GPS 코스 인정 조건을 충족하지 못한 경우,
  기록 카드에 "미인정" 작은 뱃지가 표시된다
- 동일한 코스(`courseId` 기준)에 여러 번 도전한 기록이 있는 경우, 그중
  **가장 빠른 기록에만** "최고기록" 뱃지가 표시된다 — 서로 다른 회차/기간의
  챌린지라도 물리적으로 같은 코스면 대상에 포함됨
- 기록이 하나도 없는 사용자는 심플한 빈 상태 화면을 본다
- **잘못 눌렀다 만 러닝(미완료)은 목록에서 기본으로 접힌다.** 지워지는 것이
  아니라 "미완료 러닝 N건 보기"로 언제든 펼칠 수 있다

### 3. 화면 구성

**기록 카드 — 뱃지 추가**

| 뱃지 | 노출 조건 | 스타일 제안 |
|---|---|---|
| 미인정 | `type === "온라인"` && GPS 코스 인정 실패 | 무채색 소형 뱃지 (`--muted` 배경, `--muted-foreground` 텍스트) |
| 최고기록 | `type === "온라인"` && 동일 `courseId` 내 본인 최고 기록 | 강조 뱃지 (골드/옐로우 계열, 온라인 타입 뱃지 색 `#FACC15` 계열과 통일) |
| 동기화 대기 | 로컬에만 있고 아직 서버에 업로드되지 않음 (`runs.synced_at IS NULL`) | 무채색 소형 뱃지 (`--muted` 배경, `--muted-foreground` 텍스트) |

> 두 뱃지는 동시에 노출되지 않음 (미인정 기록은 애초에 랭킹/최고기록 계산
> 대상에서 제외되므로)

> '동기화 대기' 는 위 둘과 성격이 다르다(성취가 아니라 일시적 상태) — 업로드가
> 끝나면 사라지며, 미인정/최고기록과 동시에 노출될 수 있다.

#### 4-1. 0km 기록 정책 (2026-09-20 확정)

START 를 눌렀다 만 기록이 스트릭과 총 횟수를 오염시키는 문제를 정리했다.

**판정**: 거리 `< 0.01km` **그리고** 시간 `< 60초` — **두 조건을 모두** 만족할
때만 '미완료'다. 코드 정본은 `Run` 확장의 `isIncomplete`.

**거리만으로 판정하지 않는 이유**가 이 정책의 핵심이다. 거리 0 은 성격이
다른 두 가지를 구분하지 못한다:

| 유형 | 예시 | 처리 |
|---|---|---|
| 잘못 눌렀다 만 것 | 22초 · 0.00km (`run_1789742870933776`) | 접는다 |
| 뛰었는데 GPS 를 못 잡은 것 | 1분 37초에 좌표 1개 (`run_1789297203613307`) | **남긴다** |

시간 조건이 둘을 가른다. 저장까지 막으면 후자를 통째로 잃어 "기록은 잃지
않는다" 원칙과 어긋난다. 그래서 **저장은 전부 하고, 세는 것과 보여주는 것만**
조정한다. 위 §4 의 '삭제 불가·영구 보존'은 데이터를 지키자는 것이지 표시를
강제하는 게 아니므로 충돌하지 않는다.

**적용 범위**: 기록 목록(기본 숨김) · 기록 탭 요약 통계 · 홈 총 횟수/총 거리/
총 시간 · **스트릭**(`streak.md` §2). 스트릭이 가장 중요하다 — 0km 를 세면
연속 기록이 "매일 뛰었다"가 아니라 "매일 버튼을 눌렀다"가 된다.

**요약 통계는 토글과 무관하게 항상 완료 기록만 센다.** 펼쳐 봤다고 총 횟수가
늘면 어느 쪽이 진짜인지 알 수 없다. 펼쳤을 때 카드에는 '미완료' 칩이 붙어
왜 접혀 있었는지 알 수 있다.

### 5. 데이터 요구사항 (개발자 확인 필요 영역)

**`Marathon` 타입 확장 필요** (`online-marathon.md`의 기존 타입에 추가):

```typescript
type Marathon = {
  id: string;         // 신규 — 챌린지(회차) 고유 ID
  courseId: string;   // 신규 — 코스 고유 ID, 여러 회차가 동일 코스를 공유할 수 있음
  name: string;
  distance: string;
  course: string;
  location: string;
  dday: string;
  prize: string;
  prizeEmoji: string;
  joined: boolean;
  ended: boolean;
  participants: string;
  myRank: string | null;
  myTime: string | null;
  img: string;
};
```

**`Run` 타입 확장 필요** (`run-flow.md`의 기존 확장에 추가):

```typescript
type Run = {
  // ...기존 필드 + coverImageType, coverImageUrl (run-flow.md)
  marathonChallengeId?: string;  // 신규 — type이 "온라인"일 때만, 참여한 챌린지(회차) ID
  marathonCourseId?: string;     // 신규 — type이 "온라인"일 때만, 코스 ID (뱃지 계산용)
  gpsVerified?: boolean;         // 신규 — type이 "온라인"일 때만, GPS 코스 인정 여부
};
```

**최고기록 뱃지 계산 로직**
- 특정 사용자의 `type === "온라인"` && `gpsVerified === true`인 기록들을
  `marathonCourseId` 기준으로 그룹핑
- 각 그룹에서 가장 빠른 기록(`dur` 최소값) 1건에만 "최고기록" 뱃지 부여
- **[미확정]** 챌린지가 진행 중이 아닌 시점(예: 이벤트 종료 후 개인적으로
  같은 코스를 또 뛴 경우)의 기록도 이 뱃지 계산에 포함할지 여부 →
  기본적으로는 **포함하는 것으로 가정** (개인 최고기록 개념이므로 공식
  랭킹과는 별개)

### 6. 엣지 케이스

- 동일 `courseId`에 대해 아직 한 번도 코스 인정을 받은 기록이 없는 경우
  (전부 미인정) → 최고기록 뱃지 대상 자체가 없음, 정상
- 최고기록이 동률인 경우(초 단위까지 동일) → **[미확정]** 처리 방식(둘 다
  뱃지 부여 vs 먼저 기록한 쪽 우선) — 발생 확률 낮아 우선순위는 낮음
- 기록이 전부 미완료인 경우 → 목록은 빈 상태("아직 기록이 없어요")를 보이되
  그 위에 "미완료 러닝 N건 보기" 토글이 남는다. 기록을 지운 게 아님이 보여야 한다
- 1분 이상 뛰었는데 거리가 0 인 경우(GPS 실패) → **미완료가 아니다.**
  정상 기록으로 목록·통계·스트릭에 모두 들어간다
