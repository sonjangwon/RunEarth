## 달리기 실행 로직 (Run Execution — 공통)

**최종 수정일**: 2026-08-15
**상태**: 🟢 핵심 로직 확정 · 일부 렌더링/복구 정책 미확정
**담당**: 기획/디자인 - OOO / 개발 - OOO
**적용 범위**: 일반 러닝 / 테마 러닝 / 온라인 마라톤 **공통** 트래킹·저장 로직.
코스 오버레이·완주 판정 등 러닝 타입별 차이는 `theme-running.md`,
`online-marathon.md`에서 별도로 다룬다.

### 1. 개요

기존 기능정의서에는 화면 상태 머신(idle/running/paused/stopped)만 정의돼
있고, 실제 구현에 필요한 백그라운드 추적, GPS 정밀도, 일시정지 시 동작,
대표 이미지 처리 로직이 빠져 있었다. 이번에 이 부분들을 확정한다.

### 2. 사용자 시나리오

- START 탭 → 러닝 시작. **앱이 백그라운드로 가도 GPS 추적이 계속된다**
- PAUSE 탭 → 거리·시간 누적 중단. **지도상 현재 위치 표시는 계속 갱신되지만,
  일시정지 중 이동한 구간은 경로 기록에 포함되지 않는다**
- RESUME 탭 → 누적 재개. 일시정지 중 이동으로 인해 경로 라인에 끊긴 구간이
  생길 수 있음(자연스러운 현상)
- STOP 탭 → 종료 결과 화면(RunDetailView) 진입
  - 사진 등록 안 함(기본값) → **실제 트래킹된 경로를 네온그린 라인으로 그린
    이미지**가 대표 이미지로 자동 생성/저장
  - 사진 등록함(선택, 1장만) → 등록한 사진이 대표 이미지
- 이후 "기록" 탭에서 해당 기록 상세 진입 시, **대표 이미지를 언제든 교체
  가능** (사진 ↔ 경로 이미지 자유 전환)

### 3. 화면 구성

**러닝 중 / 일시정지 중**
- 실시간 지도 + 진행 중인 실제 이동 경로 라인(네온그린, `#00E87A`)
- 상단 오버레이: 거리 / 페이스 / 경과 시간
- 일시정지 중에는 "일시정지됨" 뱃지 노출, 타이머 시각적으로 정지 표시

**종료 결과 (RunDetailView)**
- 대표 이미지 영역:
  - 사진 미등록 시: 자동 생성된 경로 렌더 이미지 — **실제 지도 배경 없이,
    네온그린 경로 라인만 심플한 어두운 단색 배경 위에 표시** (나이키 러닝
    앱 스타일의 지도+경로 합성이 아님)
  - 사진 등록 시: 등록 사진 풀블리드
- 대표 이미지 하단/오버레이: "사진 등록" 또는 "사진 변경" 버튼(선택 사항)
- km / 페이스 / 타임 / 칼로리 표시 (기존 정의 유지)

**기록 탭 상세 (해당 Run 재조회 시)**
- 대표 이미지 영역에 "대표 이미지 변경" 버튼 추가
- 탭 시 바텀시트: "사진으로 변경" / "경로 이미지로 변경" 2개 옵션

### 4. 컴포넌트 & 상태 정의

| 상태 | 위치 추적 | 거리/시간 누적 | 경로 기록 |
|---|---|---|---|
| running | ON | ON | ON |
| paused | ON (현재 위치 표시만 갱신) | OFF | OFF |
| stopped | OFF | — | — |

**대표 이미지 소스 결정**

| 조건 | 대표 이미지 |
|---|---|
| 사용자가 사진 등록함 | 등록 사진 |
| 사진 미등록(기본값) | 자동 생성 경로 이미지 (네온그린 라인) |
| 기록 탭에서 이후 변경 | 사용자가 선택한 쪽으로 교체 (양방향 전환 가능) |

### 5. 인터랙션 / 마이크로카피

- 사진 등록 영역 placeholder: "사진을 등록하지 않으면 오늘의 경로가 대표
  이미지가 돼요"
- 기록 탭 대표 이미지 변경 바텀시트: "사진으로 변경" / "경로 이미지로 변경"

### 6. 데이터 요구사항 (개발자 확인 필요 영역)

**백그라운드 위치 추적**
- iOS: "사용 중 허용"만으로는 백그라운드 추적이 안 됨 — Background Modes
  (Location updates) 설정 + 사실상 "항상 허용" 수준의 동작이 필요
- Android: Foreground Service + `ACCESS_BACKGROUND_LOCATION` 권한 필요
- `global-states.md`에서 정의한 로그인 직후 권한 요청은 **"사용 중 허용"**
  수준이므로, 러닝 시작 시점에 **추가 승격**이 필요할 수 있음
- → **[제안 기본값]** 별도 커스텀 승격 UI를 만들지 않고, OS가 자동으로
  띄우는 표준 승격 다이얼로그(예: iOS가 자체적으로 "계속 위치를 사용
  하시겠어요?"를 띄우는 경우)에 맡긴다. **[미확정]** 실기기 테스트 후
  이 기본값으로 충분한지, 별도 안내 화면이 필요한지 판단 필요

**GPS 샘플링**
- **[제안값]** 3초 간격 + 최소 이동거리 5m 필터 조합 (정지 상태에서 GPS
  노이즈로 거리가 계속 증가하는 현상 방지). 일반적인 러닝 앱 수준의
  절충안. 실측 테스트 후 조정 가능

**경로 렌더 이미지**
- GPS 좌표 배열(polyline)을 네온그린(`#00E87A`) 라인으로 렌더링, 배경은
  실제 지도 타일 없이 단색/그리드 정도만
- → **[미확정]** 렌더링을 클라이언트(앱 내 캔버스/SVG)에서 할지, 서버에서
  이미지로 생성해 URL로 내려줄지 — 서버 렌더링이 여러 화면(기록 리스트
  썸네일 등)에서 일관성 있게 재사용하기 유리함

**데이터 모델 확장**

```typescript
type Run = {
  // ...기존 필드 (date, day, km, pace, dur, kcal, type, year, month)
  coverImageType: "photo" | "route";  // 신규
  coverImageUrl: string;              // 신규 — photo면 업로드 사진, route면 자동 생성 이미지
};
```

- 대표 이미지 교체 API 필요 (`coverImageType`, `coverImageUrl` 갱신)

### 7. 엣지 케이스

- 일시정지 상태로 장시간(예: 30분 이상) 방치 시 자동 종료 처리할지 →
  **[미확정]**
- 백그라운드 중 OS가 메모리 부족 등으로 앱을 강제 종료한 경우, 진행 중이던
  러닝 데이터 복구 방법 → **[미확정]**
- 경로 렌더 이미지 생성 실패 시(GPS 포인트 부족 등) 대체 이미지 →
  **[미확정]** (예: 브랜드 로고 플레이스홀더로 대체)
- 사진 등록 후 다시 미등록 상태로 되돌릴 수 있는지 → 가능하다고 가정
  (경로 이미지로 재전환)

### 8. 완료 조건 (Acceptance Criteria)

- [ ] 앱을 백그라운드로 보내도 러닝 추적이 끊기지 않는다
- [ ] 일시정지 중 이동해도 거리/시간에 반영되지 않고, 지도상 위치 표시는 계속 갱신된다
- [ ] 사진 미등록 시 실제 경로가 네온그린 라인으로 렌더링된 이미지가 자동으로 대표 이미지가 된다
- [ ] 기록 탭 상세에서 대표 이미지를 사진/경로 이미지 중 자유롭게 교체할 수 있다
- [ ] 사진은 최대 1장만 등록 가능하다
