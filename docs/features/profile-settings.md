## 프로필 설정 (Profile Settings)

**최종 수정일**: 2026-08-15
**상태**: 🟢 전체 확정
**담당**: 기획/디자인 - OOO / 개발 - OOO
**연관 문서**: `auth-onboarding.md`(User 타입), `push-notifications.md`(알림 권한), `global-states.md`(위치 권한), `wearable-sync.md`(기기 연동 데이터 동기화)

### 0. 검토 배경

기존 `RUNNA_KR_기능정의서.md`의 설정 메뉴는 항목 이름만 있고 실제 화면
내용이 없었다. 이번 라운드에서 지금까지 정의한 인증/푸시/위치 권한 내용과
연결해 실제 내용을 채우고, 빠져 있던 계정 정보/닉네임 변경 항목을 추가했다.

### 1. 개요

프로필 탭 하위 설정 메뉴의 각 항목을 구체화한다.

### 2. 사용자 시나리오

- 프로필 > 설정 메뉴 진입
- **계정 정보** 탭 → 로그인 방식(카카오/네이버/구글), 가입일 확인, 닉네임 변경 진입점
- **닉네임 변경** 탭 → 텍스트 입력 화면, 저장 시 홈/프로필 등 전역 반영
- **기기 연동** 탭 → 애플워치/갤럭시워치 연결 목록, 탭 시 헬스 데이터 읽기
  권한 요청 → 연동 완료 시 워크아웃 자동 가져오기 시작 (`wearable-sync.md` 참조)
- **알림 및 위치 권한** 탭 → 알림 권한 상태, 위치 권한 상태를 함께 표시
- **로그아웃** 탭 → 확인 다이얼로그 → 확인 시 세션 삭제, 로그인 화면으로 강제 이동
- **회원탈퇴** 탭 → 경고 모달(30일 유예 안내) → 최종 확인 → 탈퇴 대기 상태로
  전환, 로그아웃 처리

### 3. 화면 구성

**설정 메뉴 구조**

| 그룹 | 항목 | 비고 |
|---|---|---|
| 그룹 1 | 계정 정보 | |
| 그룹 1 | 닉네임 변경 | |
| 그룹 1 | 기기 연동 | 헬스 플랫폼 경유 워크아웃 자동 가져오기 (`wearable-sync.md`) |
| 그룹 1 | 알림 및 위치 권한 | |
| 그룹 2 | 이용 약관 및 방침 | 콘텐츠는 범위 밖 |
| 그룹 2 | 자주 묻는 질문 | 콘텐츠는 범위 밖 |
| 그룹 3 | 로그아웃 | 확인 다이얼로그 포함 |
| 하단 | 회원탈퇴 | 확인 플로우 정의됨 |
| 하단 | 버전 정보 | 기존 유지 |

**계정 정보 화면**

| 요소 | 내용 |
|---|---|
| 로그인 방식 | 카카오/네이버/구글 로고 + "OO로 로그인함" — **브랜드 로고 에셋이 아직 없어** 로그인 화면과 같은 대체 아이콘을 쓴다(2026-09-26) |
| 가입일 | `createdAt` 기준 표시 |
| 닉네임 변경 | 진입 버튼 |

**닉네임 변경 화면**
- 텍스트 입력 필드 (기본값: 현재 닉네임)
- **검증 규칙 (2026-09-26 확정)** — 앞뒤 공백을 떼고 **2~12자**, 중간 공백
  금지. 그 밖의 문자는 막지 않는다(한글·영문·숫자·이모지 모두 허용).
  길이는 `runes` 로 센다 — UTF-16 코드 단위로 세면 이모지 하나가 2자가 된다.
  규칙은 `test/nickname_validation_test.dart` 가 문장 그대로 걸고 있다.
- "저장" 버튼 — 저장 시 홈/프로필/기록 등 이름이 노출되는 모든 화면에 반영
- **오프라인에서는 저장 버튼이 비활성**된다. 이름은 러닝 기록과 달리 서버
  한 곳에만 살아서 로컬에 적어둘 데가 없다(`offline-handling.md` 2 케이스 D)

**기기 연동 화면**

| 요소 | 내용 |
|---|---|
| 애플워치 | 연결 상태(연결됨/연결 안 됨) + 탭 시 HealthKit 권한 요청 |
| 갤럭시워치 | 연결 상태(연결됨/연결 안 됨) + 탭 시 Health Connect/삼성 Health 권한 요청 |

> 연동 후 실제 데이터 흐름(워크아웃 자동 가져오기, 중복 방지, 데이터
> 매핑)은 `wearable-sync.md`에서 전체 정의됨.

**알림 및 위치 권한 화면**

| 항목 | 표시 |
|---|---|
| 알림 권한 상태 | 켜짐/꺼짐 + 꺼짐이면 "설정에서 켜기" 버튼 |
| 위치 권한 상태 | 켜짐/꺼짐 + 꺼짐이면 "설정에서 켜기" 버튼 |

> **이 화면에서 권한을 요청하지 않는다 (2026-09-26).** 위치 권한은 START 에서
> 묻는 것으로 정해져 있고(`run-flow.md` 6, 2026-09-25 전수 감사에서 재확인),
> 설정 화면을 구경하는 것만으로 팝업이 뜨면 그 정책과 어긋난다. 상태 표시와
> 시스템 설정 앱으로 보내는 것까지만 한다.
>
> **설정 앱에서 돌아오면 상태를 다시 읽는다**(`AppLifecycleState.resumed`).
> 이게 없으면 방금 켠 권한이 계속 '꺼짐'으로 보여 화면의 존재 이유가 사라진다.
>
> 알림 상태는 OS 에 그대로 묻는다. `run_tracker` 가 안드로이드 외를 항상
> granted 로 보는 것은 **포그라운드 서비스가 뜨느냐**는 판단이라 성격이 다르다.

**로그아웃 확인 다이얼로그**
- "로그아웃 하시겠어요?" + "취소" / "로그아웃" 버튼
- 로그아웃 확정 시 세션 삭제(해당 기기만, `session-policy.md` 참조) → 로그인 화면으로 강제 이동

**회원탈퇴 플로우**
1. "회원탈퇴" 탭 → 1차 경고 모달: "탈퇴 시 계정과 모든 러닝 기록이 30일간
   보관돼요. 30일 이내 같은 계정으로 다시 로그인하면 자동으로 복구되고,
   30일이 지나면 영구 삭제돼요"
2. "탈퇴할게요" 최종 확인 버튼 → 탈퇴 처리 (재인증 절차 없음)
3. 처리 완료 → 세션 삭제(전체 기기), 로그인 화면으로 이동

### 4. 컴포넌트 & 상태 정의

| 상태 | 조건 | 처리 |
|---|---|---|
| 계정 정상 | 탈퇴 요청 없음 | 정상 이용 |
| 탈퇴 대기 (유예기간) | 탈퇴 확정 후 30일 이내 | 동일 계정으로 재로그인 시 자동 복구 |
| 영구 삭제 | 탈퇴 확정 후 30일 경과 | 데이터 완전 삭제 |

### 5. 인터랙션 / 마이크로카피

- 닉네임 저장 완료 토스트: "닉네임이 변경됐어요"
- 회원탈퇴 1차 경고 문구: 위 3번 참조

### 6. 데이터 요구사항 (개발자 확인 필요 영역)

```typescript
type User = {
  id: string;
  name: string;
  avatar: string;
  streak: number;
  provider: AuthProvider;
  createdAt: string;
  deletedAt: string | null;
  connectedDevices: {
    appleWatch: boolean;
    galaxyWatch: boolean;
  };
};
```

- 닉네임 변경 API 필요
- 탈퇴 처리: `deletedAt` 설정 후 30일 뒤 배치 작업으로 실제 데이터 영구 삭제
- 재로그인 시 `deletedAt`이 30일 이내인 계정이면 자동 복구

### 7. 엣지 케이스

- 탈퇴 대기 기간 중 앱은 로그인 화면만 보이며, 재로그인해야 복구가 트리거됨
- ~~닉네임 변경 시 부적절한 단어 필터링 여부~~ → **하지 않기로 했다(2026-09-26 사용자 결정).** 금칙어 목록을 직접 관리해야 하는데 닉네임이
  아직 남에게 보이지 않는다(랭킹은 MVP 이후). 랭킹이 붙을 때 다시 본다
