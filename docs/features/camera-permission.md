## 카메라 권한 (Camera Permission)

**최종 수정일**: 2026-08-15
**상태**: 🟢 정책 확정
**담당**: 기획/디자인 - OOO / 개발 - OOO
**연관 문서**: `run-flow.md`(대표 이미지 등록)

### 1. 개요

`run-flow.md`에서 정의한 "러닝 종료 시 사진 등록(1장, 선택)" 기능에
카메라 촬영 옵션을 추가한다. 기존 기능정의서는 "갤러리에서 선택"만
있었는데, 그 자리에서 바로 촬영하는 옵션도 함께 제공한다.

### 2. 사용자 시나리오

- 대표 이미지 등록/변경 버튼 탭 → 바텀시트: "카메라로 촬영" / "갤러리에서
  선택" 2개 옵션
- "카메라로 촬영" 선택 시:
  - 권한 없음 → OS 카메라 권한 다이얼로그 노출
  - 허용 → 카메라 화면으로 이동, 촬영 후 미리보기 → 등록
  - 거부 → 바텀시트로 복귀, "갤러리에서 선택"은 그대로 이용 가능 (카메라
    기능만 비활성, 앱 사용 자체는 막지 않음)
- "갤러리에서 선택"은 기존과 동일 (별도 권한 불필요 — 시스템 사진 선택기
  사용 시 전체 갤러리 접근 권한이 필요 없는 최신 OS 방식 기준)

### 3. 화면 구성

**대표 이미지 등록 바텀시트**

| 옵션 | 동작 |
|---|---|
| 카메라로 촬영 | 카메라 권한 확인 → 카메라 화면 |
| 갤러리에서 선택 | 시스템 사진 선택기 호출 (기존 정의 유지) |

### 4. 컴포넌트 & 상태 정의

| 상태 | 조건 | 처리 |
|---|---|---|
| 권한 미확인 | 카메라 최초 시도 | OS 권한 다이얼로그 노출 |
| 권한 허용 | 허용됨 | 카메라 화면 정상 진입 |
| 권한 거부 | 거부됨 | 바텀시트로 복귀, 갤러리 옵션은 유지, 별도 차단 팝업 없음 (위치 권한과 달리 핵심 기능이 아니므로 강제하지 않음) |

### 5. 인터랙션 / 마이크로카피

- 권한 거부 후 재시도 시(다시 "카메라로 촬영" 탭): OS가 재요청을
  허용하지 않는 경우 앱 자체 안내 — "카메라 권한이 꺼져 있어요. 설정에서
  켜주세요" + "설정으로 이동" 버튼 (`global-states.md`의 2차 안내 패턴과
  동일한 방식 재사용, 단 최종 차단 팝업은 없음 — 갤러리로 우회 가능하므로)

### 6. 데이터 요구사항 (개발자 확인 필요 영역)

- 카메라로 촬영한 이미지도 갤러리 선택 이미지와 동일하게
  `Run.coverImageType: "photo"`, `coverImageUrl`로 저장 (`run-flow.md` 참조)
- 촬영 이미지 압축/리사이즈 기준 → **긴 변 1080px · JPEG 85%** (2026-09-23 확정).
  한 장이 대략 200~400KB 다. 경로 PNG 도 1080 으로 렌더하고 있어 기준이 같고,
  인스타 공유(4:5)에도 충분하다. 코드는 `features/run/data/cover_photo.dart`,
  별도 이미지 패키지 없이 `image_picker` 옵션으로 처리한다
- `coverImageUrl` 은 **앱 문서 폴더의 로컬 경로**다. picker 가 주는 파일은
  캐시 폴더라 OS 가 지울 수 있어 복사해서 쓴다 (경로 PNG 와 같은 자리)

### 7. 엣지 케이스

- 카메라 권한은 이미 허용했지만 실제 기기에 카메라가 없거나 고장난 경우
  (거의 발생 안 하지만 태블릿 등) → **[미확정]**, 우선순위 낮음
- 촬영 중 앱이 백그라운드로 전환된 경우 → OS 기본 동작에 맡김 (커스텀
  처리 불필요)

- [x] 촬영한 사진이 기존 사진 등록 플로우와 동일하게 저장된다

  그대로 사용 가능하다 — **Android 에서는 권한 다이얼로그가 아예 안 뜬다.**

#### 8-1. Android 에는 카메라 권한 다이얼로그가 없다 (2026-09-23 실측)

이 문서는 "카메라 권한 다이얼로그 → 허용/거부" 를 전제로 쓰였는데, 실제
구현은 그 단계를 거치지 않는다. `image_picker` 가 **카메라 앱을 인텐트로
띄우기** 때문이다 — 우리 앱이 카메라를 직접 다루지 않으니 `CAMERA` 권한을
선언할 필요도, 요청할 필요도 없다. 에뮬레이터(Pixel 9 API35)에서 확인했다.

- 오히려 `CAMERA` 권한을 선언하면 **안 뜨던 다이얼로그가 생긴다.**
  그래서 `AndroidManifest.xml` 에 일부러 넣지 않았다
- 갤러리도 시스템 사진 선택기(Android Photo Picker)라 권한이 필요 없다.
  "This app can only access the photos you select" 안내가 뜬다 — §2 의
  "별도 권한 불필요" 와 일치한다
- **iOS 는 다르다.** `NSCameraUsageDescription`·`NSPhotoLibraryUsageDescription`
  이 없으면 고르는 순간 앱이 죽는다. `Info.plist` 에 넣어뒀지만 Mac 이 없어
  **빌드 검증은 못 했다**
- §5 의 "권한 거부 후 재시도 시 설정으로 이동 안내" 는 iOS 에서만 의미가
  있다. 지금은 넣지 않았다
