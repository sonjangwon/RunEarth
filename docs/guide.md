# 기획/개발 핸드오프 가이드

## 기능 스펙 문서 템플릿

`features/{기능명}.md` 형태로 기능마다 파일을 하나씩 만드세요. 아래 구조를 복사해서 쓰면 됩니다.

```
## {기능명}

**최종 수정일**:
**상태**: 🟢 완료 / 🟡 부분정의 / 🔴 미정의
**담당**:

### 1. 개요
### 2. 사용자 시나리오
### 3. 화면 구성
### 4. 컴포넌트 & 상태 정의
### 5. 인터랙션 / 마이크로카피
### 6. 데이터 요구사항 (개발자 확인 필요 영역)
### 7. 엣지 케이스
### 8. 완료 조건 (Acceptance Criteria)
### 9. 변경 이력
```

## CLAUDE.md 프로젝트 루트에 넣을 스니펫 예시

아래 내용을 프로젝트 루트의 `CLAUDE.md`에 추가하면, 개발자가 Claude Code로
작업할 때 세션 시작 시 자동으로 읽혀서 문서 위치를 참조하게 됩니다.

```markdown
# 프로젝트 컨텍스트

## 기획/디자인 문서
- 기능 스펙: `/docs/features/*.md` — 새 기능 작업 전 관련 문서를 먼저 확인할 것
- 전체 현황판: `/docs/feature-backlog.md`
- 디자인 시스템(컬러/타이포/컴포넌트): `RunnuR_UIUX/src/default_shadcn_theme.css`
- 각 문서 상단의 "상태" 필드 확인 — 🟡/🔴 상태 기능은 구현 전 기획자 확인 필요

## 문서 업데이트 규칙
- 기획 변경 시 해당 기능 문서의 "변경 이력" 섹션에 기록
- "[미확정]" 표시된 항목은 구현 전 반드시 논의
```

## 운영 팁

- **버전 관리**: git으로 관리하면 언제 뭐가 바뀌었는지 diff로 바로 보여서, 매번 "이거 바뀐 거예요?" 라고 물을 필요가 없어집니다.
- **[미확정] 태그**: 확실하지 않은 정책은 애매하게 넘어가지 말고 명시적으로 "미확정"이라고 써두면, 개발자가 임의로 판단하고 구현하는 걸 방지할 수 있어요.
- **스크린샷은 파일로 첨부하고 경로만 문서에 적기**: 이미지를 문서에 직접 삽입하기보다 `/docs/assets/` 같은 폴더에 두고 파일명만 참조하면 git diff가 깔끔합니다.
