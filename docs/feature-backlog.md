### 🟡 GPS 경로 렌더 3건 — **절전 모드 상황 방어로 격하** (2026-09-27)

2026-09-26 에 노트8 + 아이폰으로 동시 측정해서 나온 항목이다.
**거리는 다른 앱과 0.84% 차이로 맞는데, 지도에 그려지는 경로가 실제와 달랐다.**
근거와 수치는 `run-flow.md` 6 "2026-09-26 실측 검증".

> 🟢 **2026-09-27 대조 측정에서 원인이 절전 모드로 확정됐다.** 같은 노트8,
> 같은 빌드로 **절전만 끄고** 재측정하니 정확도 중앙값 20m → **4m**,
> 30m 초과 점프 19건 → **0건**, 끊김 3건 → **0건** 이 됐다
> (`run-flow.md` 6 "2026-09-27 대조 측정").
>
> **그래서 이 3건은 지금 만들 수 없다** — 정상 데이터에는 거를 좌표가
> **0개**라 필터를 넣어도 **동작을 검증할 대상이 없다.** 절전 모드로
> 망가진 데이터에서만 의미가 있는 방어 코드다.
>
> **실질적인 해결책은 START 전 절전 모드 안내**이고, 그쪽이 우선순위가
> 위다. 3건은 그 안내를 넣고도 남는 노이즈가 관측될 때 손댄다.

| # | 할 일 | 비고 |
|---|---|---|
| 1 | **경로 렌더에 정확도 필터** | 지도·대표 이미지에서 나쁜 좌표 제외. **거리 로직은 건드리지 않는다** |
| 2 | **`stale` 구간은 선을 끊기** | 거리에 안 더하는 구간이면 선도 이어지면 안 된다. 457m 짜리 직선이 화면에 보인다 |
| 3 | **`stale` 임계값 30초 재검토** | 24초짜리 점프 2건(268m)이 그 아래라 거리에 그대로 들어갔다 |

있으니 트랙 검증 뒤에 손대는 편이 안전하다.

2026-09-27 대조 측정에서 **`stale` 로직이 설계대로 동작한다는 것도 확인됐다.**
9/26 경로를 그냥 합산하면 3.236km 인데 저장된 거리는 2.41km — 추적하지 못한
**825m 를 정확히 빼냈다.** 다른 앱과 거리가 맞았던 게 우연이 아니었다는 뜻이다.

> ⚠️ **정확도 필터를 거리 계산에 넣지 말 것.** OpenTracks 의 50m 를 그대로
> 가져오면 이 폰에서 **거리가 23% 짧아진다**(실측 표는 `run-flow.md`).

### 🟢 START 전 절전 모드 안내 — 구현·검증 완료 (2026-09-27)

2026-09-27 대조 측정으로 **절전 모드가 경로 왜곡의 원인**이라는 게 확정되면서,
위 경로 렌더 3건을 대신하는 **실질적인 해결책**이 됐다. 같은 날 구현하고
노트8(Android 9)에서 검증까지 마쳤다. 정본: `run-flow.md` 7 '기기 절전 모드가

| 정한 것 | 값 |
|---|---|
| 읽는 방법 | **MethodChannel 직접** — `battery_plus` 안 씀. 버전 판정까지 한자리에서 끝난다 |
| 적용 범위 | **Android 9(API 28) 이하 + 절전 켜짐**. 10+ 는 OS 동작이 없어 안 띄운다 |
| 차단 여부 | **경고만.** 단 '설정 열기' 를 고르면 START 를 멈춘다 |

검증(2026-09-27 노트8): 절전 ON → 팝업 뜸 / '설정 열기' → 삼성 절전 설정 화면
이동 / 절전 OFF → 팝업 없이 카운트다운. 찌꺼기 기록 없음(`runs` 17건 그대로).

**남은 것**: 제조사 자체 절전(삼성 '최대 절전' 등)은 `isPowerSaveMode()` 가
읽지 못한다 — `run-flow.md` 6 의 [미검증] 항목으로 남아 있다.

### 🟡 날씨·미세먼지는 **샘플 값**이다 (2026-09-27 사용자 결정)

> - 🔴 10/01 더미는 실제 10/01 기록과 **경로가 바이트 단위로 같다.** 서버 데이터로
